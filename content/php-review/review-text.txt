m52-l2 Text ausgeben: echo, Strings und Verkettung
 Fast jedes Programm gibt Text aus. In PHP heißt Text  String . Es gibt zwei Schreibweisen, und der Unterschied ist wichtiger, als er aussieht:     Schreibweise  Variablen werden ersetzt?  Escape-Sequenzen wie \n  Beispiel      'einfach'   nein  nur  \'  und  \\    'Preis: $preis'  bleibt wörtlich      "doppelt"   ja  ja:  \n ,  \t ,  \" ,  \$    "Preis: $preis"  setzt den Wert ein     Strings verbindest du mit dem  Punkt :  'Hallo ' . $name . Mit  .=  hängst du an eine vorhandene Variable an. Für komplexere Ausdrücke in doppelten Anführungszeichen setzt du geschweifte Klammern:  "Summe: {$rechnung['summe']} EUR" .   Für sauber formatierte Ausgaben gibt es  sprintf : Platzhalter im Text, Werte dahinter.  %s  steht für einen String,  %d  für eine Ganzzahl,  %.2f  für eine Kommazahl mit zwei Nachkommastellen,  %05d  füllt mit Nullen auf.   Für längeren Text mit vielen Zeilen ist  Heredoc  praktisch:  &lt;&lt;&lt;TEXT … TEXT;  verhält sich wie doppelte Anführungszeichen. Die Variante mit Anführungszeichen um den Namen (Nowdoc,  &lt;&lt;&lt;'TEXT' ) wie einfache.   Probier es aus  Schreibe eine Zeile, die „Artikel 007 kostet 4,90 EUR“ ausgibt – mit  sprintf , der Artikelnummer als Zahl  7  und dem Preis als  4.9 . Tipp:  %03d  und  number_format .    Typischer Fehler  Mit  +  statt  .  rechnet PHP, statt zu verbinden:  '3' + '4'  ergibt  7 , nicht  '34' . Bei Texten ohne Zahl bricht PHP 8 sogar mit einem Fehler ab.  
CODE
<?php
declare(strict_types=1);

$vorname = 'Ada';
$punkte  = 87;
$quote   = 0.8734;

echo 'Hallo $vorname' . PHP_EOL;             // Hallo $vorname
echo "Hallo $vorname" . PHP_EOL;             // Hallo Ada
echo 'Hallo ' . $vorname . '!' . PHP_EOL;    // Hallo Ada!

$zeile = 'Punkte: ';
$zeile .= $punkte;                           // anhaengen
echo $zeile . PHP_EOL;                       // Punkte: 87

printf("%s hat %d Punkte (%.1f %%)\n", $vorname, $punkte, $quote * 100);
// Ada hat 87 Punkte (87.3 %)

echo sprintf('Bestellung %05d', 42) . PHP_EOL;   // Bestellung 00042

$mail = <<<TEXT
Hallo $vorname,

dein Ergebnis: $punkte Punkte.
TEXT;
echo $mail;


m52-l3 Zahlen und Rechnen ohne Überraschungen
 PHP kennt zwei Zahlentypen:  int  für Ganzzahlen und  float  für Kommazahlen. Die Grundrechenarten funktionieren wie erwartet – mit ein paar Eigenheiten, die du einmal bewusst gesehen haben solltest:     Ausdruck  Ergebnis  Warum      10 / 5    2  (int)  geht glatt auf      10 / 4    2.5  (float)   /  liefert bei Rest eine Kommazahl      intdiv(10, 4)    2   ganzzahlige Division, schneidet ab      10 % 4    2   Rest der Division (Modulo)      -7 % 3    -1   das Vorzeichen folgt dem linken Operanden      2 ** 10    1024   Potenz      round(2.5)    3   kaufmännisch: .5 wird von der Null weg gerundet      0.1 + 0.2 == 0.3    false   Kommazahlen sind binär nur angenähert     Der letzte Punkt ist kein PHP-Fehler, sondern betrifft jede Sprache, die Gleitkommazahlen nach IEEE 754 speichert. Für Geld gilt deshalb: in  Cent als int  rechnen und erst bei der Ausgabe formatieren.   Zur Ausgabe in deutscher Schreibweise nutzt du  number_format($zahl, 2, ',', '.')  – Dezimalkomma und Tausenderpunkt. Kurzschreibweisen sparen Tipparbeit:  $i++  erhöht um eins,  $summe += $preis  addiert.   Probier es aus  Berechne den Bruttopreis von 3 Artikeln zu je 19,99 EUR netto bei 19 % MwSt. – einmal mit Floats und einmal in Cent. Gib beide Ergebnisse mit  var_dump  aus und vergleiche.    Typischer Fehler   if ($a + $b == 0.3)  mit Kommazahlen ist fast immer falsch. Vergleiche Floats mit einer Toleranz:  abs(($a + $b) - 0.3) &lt; 0.00001  – oder rechne gleich in Ganzzahlen.  
CODE
<?php
declare(strict_types=1);

var_dump(10 / 5);        // int(2)
var_dump(10 / 4);        // float(2.5)
var_dump(intdiv(10, 4)); // int(2)
var_dump(10 % 4);        // int(2)

// Warenkorb in Cent - exakt
$preisCent = 1999;
$menge     = 3;
$nettoCent = $preisCent * $menge;                       // 5997
$bruttoCent = (int) round($nettoCent * 1.19);           // 7136

echo number_format($bruttoCent / 100, 2, ',', '.') . ' EUR' . PHP_EOL;   // 71,36 EUR

// Gleitkomma-Falle
var_dump(0.1 + 0.2 == 0.3);                    // bool(false)
var_dump(abs((0.1 + 0.2) - 0.3) < 0.00001);    // bool(true)

$zaehler = 0;
$zaehler++;           // 1
$zaehler += 5;        // 6
echo $zaehler . PHP_EOL;


m52-l4 Entscheidungen: if, else und Wahrheitswerte
 Mit  if  entscheidet dein Programm. Die Bedingung in den Klammern wird zu  true  oder  false  ausgewertet; bei true läuft der Block in geschweiften Klammern.   Vergleiche liefern Wahrheitswerte:  ===  (gleich und gleicher Typ),  !== ,  &lt; ,  &gt; ,  &lt;= ,  &gt;= . Verknüpft werden sie mit  &amp;&amp;  (und),  ||  (oder) und  !  (nicht).   Spannend wird es, wenn kein Boolean in der Bedingung steht. Dann wandelt PHP den Wert um – und diese Tabelle solltest du kennen:     wird zu false  wird zu true (Auswahl)      false ,  0 ,  0.0   jede andere Zahl, auch  -1       ""  (leerer String) und  "0"    "0.0" ,  " " ,  "false"       []  (leeres Array)   [0]  – ein Array mit Inhalt      null   jedes Objekt     Der String  "0"  ist der Klassiker: Eine Eingabe „0“ aus einem Formular gilt als false. Prüfe deshalb lieber ausdrücklich, was du meinst:  if ($eingabe !== '')  statt  if ($eingabe) .   Viele verschachtelte ifs lassen sich mit  frühem Return  (Guard Clause) entwirren: Erst die Sonderfälle abfangen und sofort zurückkehren, dann folgt der Normalfall ohne Einrückung.   Probier es aus  Schreibe eine Funktion  note(int $punkte): string , die ab 92 „sehr gut“, ab 81 „gut“, ab 67 „befriedigend“, ab 50 „ausreichend“ und darunter „nicht bestanden“ liefert – einmal mit if/elseif, einmal mit frühen Returns.    Typischer Fehler   if ($alter = 18)  ist eine  Zuweisung , kein Vergleich – die Bedingung ist dann immer wahr. Manche schreiben deshalb Vergleiche andersherum:  if (18 === $alter) . Ein fehlendes Gleichheitszeichen erzeugt so einen Fehler statt eines stillen Bugs.  
CODE
<?php
declare(strict_types=1);

function versandkosten(int $warenwertCent, string $land): int
{
    // Guard Clauses: Sonderfaelle zuerst
    if ($warenwertCent <= 0) {
        throw new InvalidArgumentException('Leerer Warenkorb');
    }
    if ($land !== 'DE') {
        return 1490;                  // Ausland pauschal
    }
    if ($warenwertCent >= 5000) {
        return 0;                     // ab 50 EUR versandkostenfrei
    }
    return 495;
}

echo versandkosten(2000, 'DE') . PHP_EOL;   // 495
echo versandkosten(6000, 'DE') . PHP_EOL;   // 0
echo versandkosten(6000, 'AT') . PHP_EOL;   // 1490

// Wahrheitswerte
var_dump((bool) '0');     // bool(false)
var_dump((bool) '0.0');   // bool(true)
var_dump((bool) []);      // bool(false)
var_dump((bool) [0]);     // bool(true)


m52-l5 Schleifen Schritt für Schritt
 Schleifen wiederholen Code. PHP hat vier Arten, und jede hat ihren Einsatzzweck:     Schleife  Wann  Mindestdurchläufe      for   Anzahl ist vorher bekannt  0      while   wiederholen, solange eine Bedingung gilt  0      do … while   erst ausführen, dann prüfen  1      foreach   jedes Element eines Arrays  0     Die  for -Schleife hat drei Teile, getrennt durch Semikolons:  Start  ( $i = 1 ),  Bedingung  ( $i &lt;= 10 ) und  Schritt  ( $i++ ). Lies sie laut: „Beginne bei 1, solange i höchstens 10 ist, erhöhe nach jedem Durchlauf um 1.“   Mit  break  verlässt du eine Schleife sofort, mit  continue  springst du zum nächsten Durchlauf. Beides ist nützlich, aber sparsam einzusetzen – zu viele Sprünge machen Schleifen schwer lesbar.   Der wichtigste Werkzeugkasten für Schleifen ist der  Trockenlauf : Lege eine Tabelle mit einer Spalte pro Variable an und gehe Durchlauf für Durchlauf durch. Genau so prüft auch die AP1 Algorithmen.   Probier es aus  Lass die Schleife unten (Einmaleins) im Kopf laufen und schreibe die ersten vier Ausgaben auf. Ändere sie dann so, dass nur gerade Ergebnisse ausgegeben werden – mit  continue .    Typischer Fehler  Endlosschleife: Wird die Variable in der Bedingung nie verändert ( while ($i &lt; 10)  ohne  $i++ ), läuft das Skript, bis PHP es nach  max_execution_time  abbricht – in der Konsole sogar unbegrenzt. Abbrechen mit  Strg + C .  
CODE
<?php
declare(strict_types=1);

// for: das kleine Einmaleins der 7
for ($i = 1; $i <= 10; $i++) {
    echo "7 x $i = " . (7 * $i) . PHP_EOL;
}

// while: Zinseszins - wie viele Jahre bis zur Verdopplung?
$kapital = 1000.0;
$jahre   = 0;
while ($kapital < 2000) {
    $kapital *= 1.05;
    $jahre++;
}
echo "Verdoppelt nach $jahre Jahren" . PHP_EOL;     // 15

// do-while: mindestens einmal
do {
    $wurf = random_int(1, 6);
    echo "Gewuerfelt: $wurf" . PHP_EOL;
} while ($wurf !== 6);

// foreach mit Schluessel und Wert, break und continue
$lager = ['Kabel' => 12, 'Maus' => 0, 'Monitor' => 3, 'Defekt' => -1];
foreach ($lager as $artikel => $bestand) {
    if ($bestand < 0) {
        break;                         // Datenfehler: abbrechen
    }
    if ($bestand === 0) {
        continue;                      // ausverkauft: ueberspringen
    }
    echo "$artikel: $bestand Stueck" . PHP_EOL;
}


m42-l1 Was PHP ist und wie ein Skript läuft
  PHP  ist eine serverseitige Skriptsprache. Der Browser sieht nie PHP-Code, sondern nur das, was das Skript ausgibt – meist HTML oder JSON. Rund drei Viertel aller Websites mit bekannter Serversprache laufen mit PHP, darunter WordPress, Shopware, Magento und alles, was mit Laravel gebaut ist.   Der Ablauf einer Anfrage ist immer gleich:    Der Browser schickt einen  HTTP-Request  an den Webserver (nginx, Apache).   Der Webserver reicht ihn an  PHP-FPM  weiter, das ein Skript startet.   Das Skript läuft von oben nach unten, schreibt eine Antwort und  endet .   Danach ist der gesamte Speicher wieder frei – der nächste Request beginnt bei null.    Dieses  Share-nothing-Prinzip  ist der wichtigste Unterschied zu Java oder Node.js: Variablen überleben keinen Request. Was bleiben soll, muss in Datenbank, Session, Cache oder Datei.   PHP-Code steht zwischen  &lt;?php  und  ?&gt; . In reinen PHP-Dateien lässt man das schließende  ?&gt;  weg, damit kein versehentliches Leerzeichen am Dateiende als Ausgabe herausrutscht. Zum Ausprobieren brauchst du keinen Webserver:  php -S localhost:8000  startet einen eingebauten Entwicklungsserver,  php datei.php  führt ein Skript in der Konsole aus und  php -a  öffnet eine interaktive Shell. 
CODE
<?php
// hallo.php  -  starten mit:  php -S localhost:8000
declare(strict_types=1);

$name = $_GET['name'] ?? 'Welt';
$stunde = (int) date('G');

$gruss = $stunde < 12 ? 'Guten Morgen' : 'Hallo';

echo "<h1>{$gruss}, " . htmlspecialchars($name) . "!</h1>";
echo '<p>PHP-Version: ' . PHP_VERSION . '</p>';

// Aufruf im Browser:  http://localhost:8000/hallo.php?name=Ada


m42-l2 Variablen, Typen und Vergleiche
 Variablen beginnen mit  $  und brauchen keine Deklaration. PHP ist  dynamisch typisiert : Der Typ hängt am Wert, nicht an der Variablen. Die skalaren Typen sind  int ,  float ,  string  und  bool , dazu kommen  array ,  object ,  null  und  callable .     Operator  Bedeutung  Beispiel      ==   gleich nach Typumwandlung   "1" == 1  → true      ===   gleich  und  gleicher Typ   "1" === 1  → false      .   Strings verketten   "a" . "b"  → "ab"      ??   Null-Koaleszenz: links, wenn nicht null   $x ?? 'Standard'       ?-&gt;   Nullsafe: Aufruf nur, wenn nicht null   $user?-&gt;name       &lt;=&gt;   Raumschiff: -1, 0 oder 1   2 &lt;=&gt; 5  → -1     Die Regel für Vergleiche ist einfach:  Immer  ===  und  !==  , außer du willst bewusst umwandeln. Mit  ==  gelten zum Beispiel  "10" == "1e1"  und  100 == "1e2"  als wahr, weil beide Seiten als Zahlen gelesen werden.   Strings in  doppelten Anführungszeichen  ersetzen Variablen ( "Hallo $name" ), solche in einfachen nicht. Für längere Texte gibt es  Heredoc  ( &lt;&lt;&lt;TXT ).   Mit  declare(strict_types=1);  wirft PHP einen  TypeError , wenn du einer Funktion mit  int -Parameter den String  "5"  übergibst. Ohne die Zeile wird still umgewandelt – und aus  "5 Äpfel"  wird mit einer Warnung die Zahl 5. 
CODE
<?php
declare(strict_types=1);

$preis  = 19.99;          // float
$menge  = 3;              // int
$artikel = 'Kabel';       // string
$aktiv  = true;           // bool
$rabatt = null;           // null

$summe = $preis * $menge;                 // 59.97
$text  = "{$menge}x {$artikel}: " . number_format($summe, 2, ',', '.') . ' EUR';

$prozent = $rabatt ?? 0;                  // 0, weil $rabatt null ist

var_dump('1' == 1);      // bool(true)   - Typumwandlung
var_dump('1' === 1);     // bool(false)  - anderer Typ
var_dump(0 == 'abc');    // bool(false)  - seit PHP 8 (vorher: true!)
var_dump(null ?? 'x');   // string(1) "x"

echo gettype($preis);    // double
echo get_debug_type($preis); // float  - die modernere Variante


m42-l3 Kontrollstrukturen und Arrays
  if ,  else ,  while ,  for  und  foreach  funktionieren wie in anderen C-ähnlichen Sprachen. Neu seit PHP 8 ist   match   – der bessere  switch :     match  vergleicht  strikt  mit  === ,  switch  lose mit  == .    match  ist ein  Ausdruck  und liefert einen Wert zurück.   Kein  break  nötig, kein versehentliches Durchfallen.   Trifft kein Zweig zu, wirft  match  einen  UnhandledMatchError  statt still nichts zu tun.     Arrays  in PHP sind geordnete Maps. Dasselbe Konstrukt dient als Liste ( [1, 2, 3] ) und als assoziatives Array ( ['name' =&gt; 'Ada'] ). Die Reihenfolge der Einfügung bleibt erhalten.     Funktion  Zweck      array_map($fn, $a)   jedes Element umwandeln      array_filter($a, $fn)   Elemente auswählen –  Schlüssel bleiben erhalten       array_reduce($a, $fn, $start)   auf einen Wert verdichten      in_array($x, $a, true)   enthalten? (drittes Argument: strikt)      array_key_exists($k, $a)   Schlüssel vorhanden, auch wenn Wert null      usort($a, $fn)   sortieren mit eigener Vergleichsfunktion     Arrays werden bei Zuweisung  kopiert  (copy-on-write), Objekte nicht. Wer ein Array in einer Funktion ändert, ändert eine Kopie – außer der Parameter ist mit  &amp;  als Referenz deklariert. 
CODE
<?php
declare(strict_types=1);

$bestellungen = [
    ['id' => 1, 'status' => 'offen',     'betrag' => 120.0],
    ['id' => 2, 'status' => 'versendet', 'betrag' =>  80.5],
    ['id' => 3, 'status' => 'offen',     'betrag' =>  42.0],
];

// Filtern: Schluessel bleiben 0 und 2 -> array_values() macht wieder 0, 1
$offen = array_values(array_filter(
    $bestellungen,
    fn (array $b) => $b['status'] === 'offen'
));

$summe = array_sum(array_column($offen, 'betrag'));    // 162.0

foreach ($bestellungen as $index => $b) {
    $label = match ($b['status']) {
        'offen'     => 'wartet auf Versand',
        'versendet' => 'unterwegs',
        'storniert' => 'abgebrochen',
    };
    echo "#{$b['id']}: {$label}\n";
}

// Destrukturierung und Spread
[$erste, $zweite] = $bestellungen;
$alle = [...$offen, ['id' => 4, 'status' => 'offen', 'betrag' => 9.9]];


m42-l4 Funktionen, Typen und Closures
 Moderne PHP-Funktionen sind vollständig typisiert. Du kannst Parameter- und Rückgabetypen angeben, und PHP prüft sie zur Laufzeit:     Nullable :  ?string  heißt „string oder null“.    Union-Typen :  int|float ,  Intersection :  Countable&amp;Iterator .    void  (gibt nichts zurück),  never  (kehrt nie zurück, wirft z. B. immer),  mixed  (alles).    Standardwerte  und  benannte Argumente :  runden(wert: 3.14159, stellen: 2) .    Variadische  Parameter:  function summe(int ...$zahlen) .    Funktionen sehen standardmäßig  keine  Variablen von außen. Es gibt keinen impliziten Zugriff auf globale Variablen – das ist gewollt. Für anonyme Funktionen gibt es zwei Formen:     Form  Zugriff auf äußere Variablen  Rumpf      function () use ($x) { … }   nur explizit per  use , als Kopie  beliebig viele Anweisungen      fn () =&gt; …   automatisch, als Kopie  genau ein Ausdruck     Mit  use (&amp;$x)  übergibst du eine Referenz, dann wirken Änderungen nach außen. Seit PHP 8.1 erzeugt  strlen(...)  (drei Punkte) eine Closure aus einer bestehenden Funktion – die  First-class callable syntax . 
CODE
<?php
declare(strict_types=1);

function brutto(float $netto, float $steuersatz = 0.19): float
{
    return round($netto * (1 + $steuersatz), 2);
}

echo brutto(100);                       // 119
echo brutto(100, steuersatz: 0.07);     // 107  (benanntes Argument)

function findeKunde(int $id): ?array    // array oder null
{
    $kunden = [7 => ['name' => 'Ada']];
    return $kunden[$id] ?? null;
}

function abbrechen(string $grund): never
{
    throw new RuntimeException($grund);
}

// Closures
$faktor = 3;
$mal  = function (int $x) use ($faktor): int { return $x * $faktor; };
$mal2 = fn (int $x): int => $x * $faktor;     // $faktor automatisch

$zaehler = 0;
$erhoehe = function () use (&$zaehler): void { $zaehler++; };
$erhoehe(); $erhoehe();
echo $zaehler;                          // 2

$laengen = array_map(strlen(...), ['PHP', 'Laravel']);   // [3, 7]


m53-l1 Arrays anlegen, lesen und verändern
 Ein  Array  speichert viele Werte unter einem Namen. Jeder Wert hat einen  Schlüssel  (Key): entweder automatisch eine Zahl ab 0 oder ein selbst gewählter String.     Aufgabe  Code     anlegen   $farben = ['rot', 'grün'];      hinten anhängen   $farben[] = 'blau';      lesen   $farben[0]  →  'rot'      ändern   $farben[1] = 'gelb';      Anzahl   count($farben)      Schlüssel vorhanden?   array_key_exists('k', $a)  oder  isset($a['k'])      entfernen   unset($farben[0]);       isset()  und  array_key_exists()  unterscheiden sich in einem Punkt: Steht unter dem Schlüssel der Wert  null , liefert  isset()  false,  array_key_exists()  aber true.    unset()  entfernt einen Eintrag, nummeriert die übrigen aber  nicht neu . Nach  unset($farben[0])  beginnt das Array bei Index 1. Brauchst du wieder eine lückenlose Liste, hilft  array_values() .   Arrays können Arrays enthalten. So bildest du Tabellen ab: eine Liste von Zeilen, jede Zeile ein assoziatives Array. Zum Anschauen beim Lernen sind  print_r()  und  var_dump()  unverzichtbar.   Probier es aus  Lege ein Array mit drei Kunden an (jeweils  name  und  stadt ). Gib mit  foreach  alle Kunden aus Köln aus. Füge danach einen vierten Kunden hinzu und gib die Anzahl aus.    Typischer Fehler  Zugriff auf einen Schlüssel, den es nicht gibt, erzeugt eine Warnung „Undefined array key“. Mit dem Null-Koaleszenz-Operator bleibt es ruhig:  $kunde['telefon'] ?? 'keine Angabe' .  
CODE
<?php
declare(strict_types=1);

$kunden = [
    ['name' => 'Ada',    'stadt' => 'Koeln',  'telefon' => null],
    ['name' => 'Grace',  'stadt' => 'Berlin', 'telefon' => '030 123'],
    ['name' => 'Linus',  'stadt' => 'Koeln',  'telefon' => '0221 99'],
];

$kunden[] = ['name' => 'Margaret', 'stadt' => 'Hamburg', 'telefon' => null];
echo count($kunden) . PHP_EOL;                         // 4

foreach ($kunden as $k) {
    if ($k['stadt'] === 'Koeln') {
        echo $k['name'] . ': ' . ($k['telefon'] ?? 'keine Angabe') . PHP_EOL;
    }
}

var_dump(isset($kunden[0]['telefon']));                // bool(false) - Wert ist null
var_dump(array_key_exists('telefon', $kunden[0]));     // bool(true)

unset($kunden[0]);
print_r(array_keys($kunden));       // [1, 2, 3]  - keine Neu-Nummerierung
$kunden = array_values($kunden);    // wieder 0, 1, 2

// Destrukturierung mit Schluesseln
['name' => $n, 'stadt' => $s] = $kunden[0];
echo "$n wohnt in $s" . PHP_EOL;                      // Grace wohnt in Berlin


m53-l2 Sortieren und Umformen
 PHP hat viele Sortierfunktionen. Sie unterscheiden sich in zwei Fragen:  Wonach  wird sortiert (Wert oder Schlüssel) und  bleiben die Schlüssel  erhalten?     Funktion  sortiert nach  Schlüssel      sort  /  rsort   Wert auf- / absteigend  werden neu nummeriert      asort  /  arsort   Wert  bleiben erhalten      ksort  /  krsort   Schlüssel  bleiben erhalten      usort   eigene Vergleichsfunktion  werden neu nummeriert      uasort   eigene Vergleichsfunktion  bleiben erhalten     Alle Sortierfunktionen arbeiten  auf dem Array selbst  und geben nur  true  zurück. Der Raumschiff-Operator  &lt;=&gt;  macht Vergleichsfunktionen kurz: Er liefert -1, 0 oder 1. Mehrere Sortierkriterien vergleichst du, indem du Arrays vergleichst:  [$a['stadt'], $a['name']] &lt;=&gt; [$b['stadt'], $b['name']] .   Zum Umformen gibt es Funktionen, die neue Arrays zurückgeben und das Original unverändert lassen:  array_map  (umwandeln),  array_filter  (auswählen),  array_column  (eine Spalte herausziehen),  array_combine  (zwei Listen zu Schlüssel und Wert),  array_unique  (Duplikate entfernen) und  array_slice  (Ausschnitt).   Probier es aus  Sortiere die Produktliste aus dem Beispiel absteigend nach Preis, bei gleichem Preis aufsteigend nach Name. Gib danach nur die Namen als kommagetrennten Text aus ( array_column  +  implode ).    Typischer Fehler   $sortiert = sort($zahlen);  – danach ist  $sortiert  nicht das sortierte Array, sondern  true . Sortiert wurde  $zahlen  selbst.  
CODE
<?php
declare(strict_types=1);

$produkte = [
    ['name' => 'Maus',    'preis' => 1990],
    ['name' => 'Kabel',   'preis' =>  499],
    ['name' => 'Adapter', 'preis' => 1990],
];

// Absteigend nach Preis, dann aufsteigend nach Name
usort($produkte, fn (array $a, array $b) =>
    [$b['preis'], $a['name']] <=> [$a['preis'], $b['name']]
);

echo implode(', ', array_column($produkte, 'name')) . PHP_EOL;   // Adapter, Maus, Kabel

// Assoziativ sortieren, Schluessel behalten
$punkte = ['Ada' => 87, 'Grace' => 95, 'Linus' => 71];
arsort($punkte);
print_r($punkte);         // Grace => 95, Ada => 87, Linus => 71

// Umformen ohne das Original zu aendern
$preiseEuro = array_map(fn (array $p) => $p['preis'] / 100, $produkte);
$guenstig   = array_filter($produkte, fn (array $p) => $p['preis'] < 1000);
$nachName   = array_combine(array_column($produkte, 'name'), array_column($produkte, 'preis'));
// ['Adapter' => 1990, 'Maus' => 1990, 'Kabel' => 499]

 Ein großer Teil der Programmierarbeit ist Textverarbeitung: Eingaben säubern, Daten zerlegen, Ausgaben zusammensetzen. <?php
declare(strict_types=1);

// Eingaben saeubern
$email = mb_strtolower(trim('  Ada@Example.COM '));    // ada@example.com

// Muster pruefen
foreach (['50667', '5066', '506671', 'abcde'] as $plz) {
    $ok = preg_match('/^\d{5}$/', $plz) === 1;
    echo $plz . ': ' . ($ok ? 'gueltig' : 'ungueltig') . PHP_EOL;
}

// Slug fuer URLs

m53-l4 Datum und Zeit richtig behandeln
 Datumsrechnung ist eine der häufigsten Fehlerquellen in Software: Zeitzonen, Sommerzeit, Monatsenden. PHP bietet dafür die Klassen  DateTime  und  DateTimeImmutable . Nimm grundsätzlich  DateTimeImmutable :     DateTime::modify()  verändert das Objekt selbst. Wer dasselbe Objekt an zwei Stellen nutzt, verschiebt unbemerkt beide Termine.    DateTimeImmutable::modify()  gibt ein  neues  Objekt zurück, das Original bleibt.      Format  Bedeutung  Beispiel      d.m.Y   Tag.Monat.Jahr  09.10.2026      H:i   Stunde:Minute (24 h)  14:05      Y-m-d   ISO-Datum für Datenbanken  2026-10-09      D, d M Y   englische Kurzform  Fri, 09 Oct 2026     Vorsicht bei Monaten:  modify('+1 month')  auf den 31. Januar ergibt nicht den 28. Februar, sondern den  3. März  – PHP rechnet „31. Februar“ und läuft über. Für Monatsenden gibt es  modify('last day of next month') .    Zeitzonen:  Speichere Zeitpunkte in der Datenbank in  UTC  und rechne erst für die Anzeige in  Europe/Berlin  um. So überstehen deine Daten jede Sommerzeitumstellung. Laravel arbeitet mit  Carbon , einer Erweiterung von DateTime mit lesbaren Methoden wie  now()-&gt;addDays(14) .   Probier es aus  Berechne, wie viele Tage es noch bis zu deiner AP1 sind:  diff()  zwischen heute und dem Prüfungsdatum, Ausgabe über  -&gt;days .  
CODE
<?php
declare(strict_types=1);

$zone   = new DateTimeZone('Europe/Berlin');
$heute  = new DateTimeImmutable('today', $zone);
$frist  = $heute->modify('+14 days');          // $heute bleibt unveraendert

echo $heute->format('d.m.Y') . ' -> ' . $frist->format('d.m.Y') . PHP_EOL;

// Die Monatsfalle
$januar = new DateTimeImmutable('2026-01-31');
echo $januar->modify('+1 month')->format('Y-m-d') . PHP_EOL;                // 2026-03-03
echo $januar->modify('last day of next month')->format('Y-m-d') . PHP_EOL;  // 2026-02-28

// Abstand in Tagen
$pruefung = new DateTimeImmutable('2027-03-02', $zone);
echo 'Noch ' . $heute->diff($pruefung)->days . ' Tage bis zur AP1' . PHP_EOL;

// Speichern in UTC, anzeigen in Berlin
$utc = $heute->setTimezone(new DateTimeZone('UTC'))->format('Y-m-d H:i:s');
echo "In der Datenbank: $utc" . PHP_EOL;


m43-l1 Formulare verarbeiten und Ausgaben absichern
 PHP stellt Request-Daten in  Superglobals  bereit:  $_GET  (Query-String),  $_POST  (Formulardaten),  $_FILES  (Uploads),  $_COOKIE ,  $_SERVER  (Header, Methode, Pfad) und  $_SESSION . Alles darin kommt vom Client und ist damit  nicht vertrauenswürdig .   Die Grundregel lautet:  Eingaben validieren, Ausgaben kodieren .     Validieren  beim Eingang: Ist es vorhanden, hat es den richtigen Typ, Bereich und Format?  filter_var($email, FILTER_VALIDATE_EMAIL)  hilft bei Standardformaten.    Kodieren  bei der Ausgabe, passend zum Kontext: in HTML mit  htmlspecialchars($s, ENT_QUOTES, 'UTF-8') , in SQL über Prepared Statements, in JSON über  json_encode() .    Ohne Kodierung entsteht  Cross-Site-Scripting (XSS) : Ein Angreifer schickt als Name  &lt;script&gt;…&lt;/script&gt; , und jeder Besucher führt das Skript aus.   Nach einem erfolgreichen POST leitet man um, statt direkt HTML auszugeben. Dieses  Post/Redirect/Get -Muster verhindert, dass ein Neuladen der Seite das Formular erneut abschickt. 
CODE
<?php
declare(strict_types=1);

function e(string $s): string
{
    return htmlspecialchars($s, ENT_QUOTES, 'UTF-8');
}

$fehler = [];
$name   = '';
$email  = '';

if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    $name  = trim((string) ($_POST['name'] ?? ''));
    $email = trim((string) ($_POST['email'] ?? ''));

    if ($name === '' || mb_strlen($name) > 100) {
        $fehler['name'] = 'Bitte einen Namen mit hoechstens 100 Zeichen angeben.';
    }
    if (filter_var($email, FILTER_VALIDATE_EMAIL) === false) {
        $fehler['email'] = 'Bitte eine gueltige E-Mail-Adresse angeben.';
    }

    if ($fehler === []) {
        // ... speichern ...
        header('Location: /danke.php', true, 303);   // Post/Redirect/Get
        exit;
    }
}
?>
<form method="post">
  <input name="name"  value="<?= e($name) ?>">
  <?php if (isset($fehler['name'])): ?><p class="fehler"><?= e($fehler['name']) ?></p><?php endif ?>
  <input name="email" value="<?= e($email) ?>">
  <button>Senden</button>
</form>


m43-l2 Sessions, Cookies und Passwörter
 HTTP ist zustandslos. Eine  Session  merkt sich Daten zwischen Requests: PHP speichert sie serverseitig und schickt dem Browser nur eine zufällige Session-ID als Cookie.  session_start()  muss  vor jeder Ausgabe  aufgerufen werden, weil es einen Header setzt.   Für Login-Systeme gelten drei feste Regeln:     Passwörter nie selbst hashen.   password_hash($pw, PASSWORD_DEFAULT)  nimmt einen langsamen, gesalzenen Algorithmus (bcrypt bzw. Argon2),  password_verify()  prüft. MD5 oder SHA-256 sind für Passwörter ungeeignet, weil sie zu schnell sind.    Nach dem Login   session_regenerate_id(true)  aufrufen. Sonst kann ein Angreifer, der dem Opfer vorher eine Session-ID untergeschoben hat, diese weiterverwenden ( Session Fixation ).    Cookie-Flags  setzen:  HttpOnly  (kein Zugriff per JavaScript),  Secure  (nur HTTPS),  SameSite=Lax  (Schutz gegen viele CSRF-Angriffe).    Unterscheide  Authentifizierung  (wer bist du?) von  Autorisierung  (was darfst du?). Die Session sagt nur, wer eingeloggt ist. Ob dieser Benutzer die Rechnung Nr. 4711 sehen darf, musst du bei jedem Zugriff extra prüfen. 
CODE
<?php
declare(strict_types=1);

session_start([
    'cookie_httponly' => true,
    'cookie_secure'   => true,
    'cookie_samesite' => 'Lax',
]);

// Registrierung
$hash = password_hash($_POST['passwort'], PASSWORD_DEFAULT);
// -> z. B. "$2y$12$Qm..."  (Algorithmus, Kosten und Salt stecken im Hash)

// Login
function login(PDO $db, string $email, string $passwort): bool
{
    $stmt = $db->prepare('SELECT id, passwort_hash FROM benutzer WHERE email = ?');
    $stmt->execute([$email]);
    $user = $stmt->fetch();

    if (!$user || !password_verify($passwort, $user['passwort_hash'])) {
        return false;                       // gleiche Meldung fuer beide Faelle!
    }

    if (password_needs_rehash($user['passwort_hash'], PASSWORD_DEFAULT)) {
        // Hash mit aktuellen Parametern neu speichern ...
    }

    session_regenerate_id(true);            // Schutz vor Session Fixation
    $_SESSION['user_id'] = $user['id'];
    return true;
}


m43-l3 Datenbankzugriff mit PDO und Prepared Statements
  PDO  (PHP Data Objects) ist die einheitliche Datenbankschnittstelle von PHP für MySQL, MariaDB, PostgreSQL, SQLite und weitere. Laravel baut intern darauf auf.   Die wichtigste Regel:  Nie Benutzereingaben in SQL-Strings einbauen.  Aus  "… WHERE email = '$email'"  wird mit der Eingabe  ' OR '1'='1  eine Abfrage, die alle Zeilen liefert –  SQL-Injection . Stattdessen nimmst du  Prepared Statements : Die Abfrage mit Platzhaltern geht getrennt von den Werten an die Datenbank, die Werte können die Struktur nicht mehr verändern.     Option  Empfehlung  Warum      ATTR_ERRMODE    ERRMODE_EXCEPTION   Fehler werfen statt still false liefern (Standard seit PHP 8)      ATTR_DEFAULT_FETCH_MODE    FETCH_ASSOC   nur Spaltennamen, keine doppelten Zahl-Indizes      ATTR_EMULATE_PREPARES    false   echte Prepared Statements, korrekte Typen     Platzhalter gehen nur für  Werte , nicht für Tabellen- oder Spaltennamen. Wenn der Benutzer eine Sortierspalte wählt, prüfst du sie gegen eine  Whitelist .   Mehrere Schreibvorgänge, die nur gemeinsam Sinn ergeben (Bestellung und Positionen), gehören in eine  Transaktion :  beginTransaction() ,  commit() , bei Fehler  rollBack() . 
CODE
<?php
declare(strict_types=1);

$db = new PDO(
    'mysql:host=127.0.0.1;dbname=shop;charset=utf8mb4',
    'shop_user',
    getenv('DB_PASSWORD') ?: '',
    [
        PDO::ATTR_ERRMODE            => PDO::ERRMODE_EXCEPTION,
        PDO::ATTR_DEFAULT_FETCH_MODE => PDO::FETCH_ASSOC,
        PDO::ATTR_EMULATE_PREPARES   => false,
    ]
);

// FALSCH - SQL-Injection:
// $db->query("SELECT * FROM kunden WHERE email = '{$_GET['email']}'");

// RICHTIG - benannte Platzhalter
$stmt = $db->prepare('SELECT id, name FROM kunden WHERE email = :email');
$stmt->execute(['email' => $_GET['email'] ?? '']);
$kunde = $stmt->fetch();                     // array oder false

// Spaltennamen: Whitelist statt Platzhalter
$erlaubt = ['name', 'erstellt_am'];
$sort = in_array($_GET['sort'] ?? '', $erlaubt, true) ? $_GET['sort'] : 'name';
$liste = $db->query("SELECT id, name FROM kunden ORDER BY {$sort}")->fetchAll();

// Transaktion
try {
    $db->beginTransaction();
    $db->prepare('INSERT INTO bestellungen (kunde_id) VALUES (?)')->execute([$kunde['id']]);
    $bestellId = (int) $db->lastInsertId();
    $db->prepare('INSERT INTO positionen (bestellung_id, artikel_id) VALUES (?, ?)')
       ->execute([$bestellId, 42]);
    $db->commit();
} catch (Throwable $e) {
    $db->rollBack();
    throw $e;
}


m54-l1 Dateien lesen und schreiben
 Für kleine Dateien genügen zwei Funktionen:  file_get_contents()  liest alles in einen String,  file_put_contents()  schreibt einen String. Mit dem Flag  FILE_APPEND  wird angehängt statt überschrieben,  LOCK_EX  sperrt die Datei während des Schreibens gegen gleichzeitige Zugriffe.   Große Dateien liest du  zeilenweise , damit nicht die ganze Datei im Speicher landet: mit  fopen()  und  fgets()  oder bequemer mit  SplFileObject . Für CSV gibt es  fgetcsv()  und  fputcsv() , die Anführungszeichen und Trennzeichen in den Feldern korrekt behandeln.    Deutsche Excel-Versionen erwarten das  Semikolon  als Trennzeichen. Erlaube nur bekannte Namen aus einer Whitelist oder entferne Verzeichnisanteile mit  basename() .   Probier es aus  Schreibe drei Bestellungen als CSV mit Semikolon in  bestellungen.csv , öffne die Datei in einer Tabellenkalkulation und lies sie anschließend mit  SplFileObject  wieder ein.

$erlaubt = ['agb.pdf', 'preise.pdf'];
$wunsch  = $_GET['datei'] ?? '';
if (!in_array($wunsch, $erlaubt, true)) {

m54-l2 JSON sauber verarbeiten
 JSON ist das Austauschformat für APIs, Konfigurationen und Webhooks. In PHP heißen die beiden Werkzeuge  json_encode()  und  json_decode()  – und beide haben Optionen, die man kennen muss.     Flag  Wirkung      JSON_THROW_ON_ERROR   wirft eine  JsonException  statt still  null  bzw.  false  zu liefern      JSON_UNESCAPED_UNICODE   „Müller“ statt „Müller“      JSON_UNESCAPED_SLASHES    https://…  statt  https:\/\/…       JSON_PRETTY_PRINT   eingerückt, gut lesbar     Ohne  JSON_THROW_ON_ERROR  liefert  json_decode()  bei kaputtem JSON einfach  null  – genau wie bei dem gültigen JSON  null . Den Unterschied siehst du nur mit  json_last_error() . Deshalb gilt:  immer mit JSON_THROW_ON_ERROR .   Der zweite Parameter von  json_decode()  entscheidet über die Form:  true  liefert assoziative Arrays,  false  (Standard) Objekte vom Typ  stdClass . Ab PHP 8.3 prüft  json_validate()  ein JSON nur auf Gültigkeit, ohne es komplett aufzubauen.   Ein von außen kommendes JSON ist eine Eingabe wie jede andere: Nach dem Dekodieren prüfst du, ob die erwarteten Felder da sind und den richtigen Typ haben.   Typischer Fehler  Leere PHP-Arrays werden zu  [] , auch wenn ein Objekt  {}  erwartet wird. Wer  {}  braucht, übergibt  new stdClass()  oder nutzt das Flag  JSON_FORCE_OBJECT .  
CODE
<?php
declare(strict_types=1);

$bestellung = ['kunde' => 'Müller', 'web' => 'https://shop.example', 'positionen' => [['sku' => 'A1', 'menge' => 2]]];

$json = json_encode(
    $bestellung,
    JSON_THROW_ON_ERROR | JSON_UNESCAPED_UNICODE | JSON_UNESCAPED_SLASHES | JSON_PRETTY_PRINT
);
echo $json . PHP_EOL;

// Dekodieren - mit Fehlerbehandlung und Pruefung der Struktur
function leseWebhook(string $roh): array
{
    try {
        $daten = json_decode($roh, true, 512, JSON_THROW_ON_ERROR);
    } catch (JsonException $e) {
        throw new InvalidArgumentException('Kein gueltiges JSON: ' . $e->getMessage(), previous: $e);
    }

    if (!is_array($daten) || !isset($daten['event'], $daten['id']) || !is_string($daten['event'])) {
        throw new InvalidArgumentException('Unerwartete Struktur');
    }
    return $daten;
}

var_dump(json_validate('{"ok": true}'));   // bool(true)  - ab PHP 8.3
var_dump(json_validate('{ok: true}'));     // bool(false)


m54-l3 HTTP-Anfragen an andere Dienste
 Moderne Anwendungen sprechen ständig mit anderen Diensten: Zahlungsanbieter, Versanddienstleister, Wetter-APIs. In reinem PHP ist  Guzzle  der Standard-HTTP-Client ( composer require guzzlehttp/guzzle ); auch der HTTP-Client von Laravel baut darauf auf.   Drei Regeln, die in jedem Code-Review geprüft werden:     Immer ein Timeout.  Ohne Timeout wartet dein Prozess unter Umständen minutenlang auf einen hängenden Dienst – und mit ihm der Benutzer.    Fehler gezielt behandeln.  Guzzle wirft standardmäßig eine  ClientException  bei 4xx, eine  ServerException  bei 5xx und eine  ConnectException , wenn der Dienst gar nicht erreichbar ist.    Zugangsdaten aus der Umgebung  lesen, nie im Code ablegen.      Option  Zweck      base_uri   gemeinsamer Anfang aller URLs      timeout  /  connect_timeout   Gesamtdauer / Verbindungsaufbau in Sekunden      query   Parameter für den Query-String      json   Body als JSON senden, setzt den Content-Type      headers   z. B.  Authorization: Bearer …      Ob ein Fehler einen neuen Versuch lohnt, hängt von der Ursache ab: Bei 5xx und Verbindungsfehlern ja, mit wachsender Wartezeit. Bei 4xx nein – die Anfrage selbst ist falsch und wird auch beim zweiten Mal abgelehnt. 
CODE
<?php
declare(strict_types=1);

use GuzzleHttp\Client;
use GuzzleHttp\Exception\ClientException;
use GuzzleHttp\Exception\ConnectException;
use GuzzleHttp\Exception\ServerException;

$client = new Client([
    'base_uri'        => 'https://api.versand.example/v2/',
    'timeout'         => 5.0,
    'connect_timeout' => 2.0,
    'headers'         => ['Authorization' => 'Bearer ' . getenv('VERSAND_TOKEN')],
]);

function sendungsstatus(Client $client, string $nummer): ?string
{
    for ($versuch = 1; $versuch <= 3; $versuch++) {
        try {
            $antwort = $client->get('sendungen/' . rawurlencode($nummer));
            $daten = json_decode((string) $antwort->getBody(), true, 512, JSON_THROW_ON_ERROR);
            return $daten['status'] ?? null;
        } catch (ClientException $e) {
            if ($e->getResponse()->getStatusCode() === 404) {
                return null;                       // unbekannte Sendung - kein neuer Versuch
            }
            throw $e;                              // andere 4xx: Fehler im eigenen Code
        } catch (ServerException | ConnectException $e) {
            if ($versuch === 3) {
                throw $e;
            }
            usleep(200_000 * 2 ** $versuch);       // 0,4 s, dann 0,8 s warten
        }
    }
    return null;
}


m54-l4 Fehler, Exceptions und Logging in der Praxis
 Fehlerbehandlung entscheidet darüber, ob du um 3 Uhr nachts in fünf Minuten weißt, was los ist – oder in fünf Stunden. Drei Bausteine gehören zusammen:     Exceptions  für Situationen, die der aufrufende Code behandeln kann oder soll.  Klassen in PHP folgen den bekannten OOP-Regeln: Eigenschaften und Methoden mit den Sichtbarkeiten  public ,  protected  und  private . Modernes PHP spart dabei viel Schreibarbeit:     Constructor Property Promotion  (PHP 8.0): Sichtbarkeit direkt am Konstruktorparameter deklariert Eigenschaft und Zuweisung in einem.    readonly-Eigenschaften  (8.1) dürfen genau einmal gesetzt werden, danach wirft jede Änderung einen Fehler. Eine  readonly class  (8.2) macht alle Eigenschaften readonly.    Statische  Methoden gehören zur Klasse, nicht zum Objekt – praktisch für  benannte Konstruktoren  wie  Geld::euro(19.99) .    Objekte werden als  Handle  übergeben: Weist du ein Objekt einer zweiten Variablen zu, zeigen beide auf dasselbe Objekt. Eine echte Kopie erzeugt  clone .   Unveränderliche  Value Objects  sind ein Kernwerkzeug für sauberen Code: Ein  Geld -Objekt aus Betrag in Cent und Währung kann nie in einem ungültigen Zustand existieren. Für Fabrikmethoden in Basisklassen ist  new static()  darum meist richtig.

<?php
declare(strict_types=1);

final readonly class Geld
{
    private function __construct(
        public int $cent,
        public string $waehrung,
    ) {
        if ($cent < 0) {
            throw new InvalidArgumentException('Betrag darf nicht negativ sein.');
        }
    }

    public static function euro(float $betrag): self
    {
        return new self((int) round($betrag * 100), 'EUR');
    }

    public function plus(Geld $anderes): self
    {
        if ($anderes->waehrung !== $this->waehrung) {
            throw new LogicException('Waehrungen unterschiedlich.');
        }
        return new self($this->cent + $anderes->cent, $this->waehrung);
    }

    public function format(): string
    {
        return number_format($this->cent / 100, 2, ',', '.') . ' ' . $this->waehrung;
    }
}

m44-l3 Enums und Exceptions
  Enums  (PHP 8.1) ersetzen Konstanten-Sammlungen und magische Strings. Statt  $status = 'versendet'  mit Tippfehler-Gefahr schreibst du  Status::Versendet , und der Typ  Status  lässt nur gültige Werte zu.     Pure Enums  haben nur Fälle:  case Offen;     Backed Enums  haben einen skalaren Wert für Datenbank oder API:  enum Status: string { case Offen = 'offen'; }     Status::from('offen')  wandelt um und wirft bei unbekanntem Wert,  tryFrom()  liefert dann null.    Status::cases()  liefert alle Fälle – ideal für Auswahllisten.   Enums können Methoden und Interfaces haben, aber keinen Zustand.     Exceptions  melden Fehler, die der Aufrufer behandeln soll. Die Hierarchie:  Throwable  ist die Wurzel. Darunter liegen  Error  für Programmierfehler wie  TypeError  und  Exception  für erwartbare Probleme. Mit  catch (Throwable $e)  fängst du beides.   Gute Praxis: Eigene,  fachlich benannte  Exceptions ( LagerbestandZuNiedrig ) statt generischer  Exception . Fange nur dort, wo du wirklich etwas tun kannst. Wenn du eine Exception in eine eigene umwandelst, übergib die ursprüngliche als  previous , sonst ist die Ursache im Log weg.

<?php
declare(strict_types=1);

enum BestellStatus: string
{
    case Offen     = 'offen';
    case Bezahlt   = 'bezahlt';
    case Versendet = 'versendet';
    case Storniert = 'storniert';

    public function label(): string
    {
        return match ($this) {
            self::Offen     => 'Wartet auf Zahlung',
            self::Bezahlt   => 'Bezahlt',
            self::Versendet => 'Unterwegs',
            self::Storniert => 'Storniert',
        };
    }

    public function darfWechselnZu(self $neu): bool
    {
        return in_array($neu, match ($this) {
            self::Offen     => [self::Bezahlt, self::Storniert],
            self::Bezahlt   => [self::Versendet, self::Storniert],
            default         => [],
        }, true);
    }
}

final class UngueltigerStatuswechsel extends DomainException
{
    public static function von(BestellStatus $alt, BestellStatus $neu): self
    {
        return new self("Wechsel von {$alt->value} nach {$neu->value} nicht erlaubt.");
    }
}

$status = BestellStatus::from('offen');
$neu    = BestellStatus::tryFrom($_GET['status'] ?? '') ?? BestellStatus::Offen;

try {
    if (!$status->darfWechselnZu($neu)) {
        throw UngueltigerStatuswechsel::von($status, $neu);
    }
} catch (UngueltigerStatuswechsel $e) {
    echo $e->getMessage();
} finally {
    // laeuft immer - z. B. Datei schliessen, Lock freigeben
}

m55-l1 Generatoren: große Datenmengen mit wenig Speicher
 Eine normale Funktion baut ihr Ergebnis komplett auf und gibt es dann zurück. Bei einer Million Zeilen liegt dann eine Million Zeilen im Speicher. Ein  Generator  liefert die Werte stattdessen  einzeln auf Anfrage : Jede Funktion mit  yield  ist ein Generator.    Bei jedem  yield  pausiert die Funktion und gibt einen Wert heraus.   Die  foreach -Schleife des Aufrufers holt den nächsten Wert, und die Funktion läuft dort weiter, wo sie pausiert hat.    yield $schluessel =&gt; $wert  liefert auch Schlüssel,  yield from  reicht die Werte eines anderen Generators durch.    Generatoren sind  faul  (lazy): Bricht der Aufrufer nach zehn Werten ab, wird der Rest gar nicht erst berechnet. Das macht sie ideal für Importe, Exporte und Pipelines, in denen mehrere Schritte hintereinander geschaltet werden.   Laravel nutzt dasselbe Prinzip in  LazyCollection  und  Model::lazy()  bzw.  lazyById() .   Probier es aus  Schreibe einen Generator  zahlen(int $bis) , der von 1 bis  $bis  zählt. Miss mit  memory_get_peak_usage()  den Speicher einmal für  range(1, 1_000_000)  und einmal für den Generator.  
CODE
<?php
declare(strict_types=1);

/** @return Generator<int, array> */
function leseZeilen(string $pfad): Generator
{
    $datei = new SplFileObject($pfad);
    while (!$datei->eof()) {
        $zeile = $datei->fgetcsv(';');
        if ($zeile === [null] || $zeile === false) {
            continue;
        }
        yield $datei->key() => $zeile;         // pausiert hier
    }
}

function nurGueltige(iterable $zeilen): Generator
{
    foreach ($zeilen as $nr => $z) {
        if (count($z) === 3 && is_numeric(str_replace(',', '.', $z[2]))) {
            yield $nr => $z;
        }
    }
}

// Pipeline: nichts wird vorab geladen, jede Zeile fliesst einzeln durch
$summe = 0;
foreach (nurGueltige(leseZeilen(__DIR__ . '/umsatz.csv')) as $nr => [$datum, $kunde, $betrag]) {
    $summe += (int) round((float) str_replace(',', '.', $betrag) * 100);
}
printf("Umsatz: %.2f EUR, Spitzenspeicher: %d KB\n", $summe / 100, memory_get_peak_usage() / 1024);

<?php
declare(strict_types=1);

interface Versandart
{
    public function passtZu(string $land, int $gewichtGramm): bool;
    public function kostenCent(int $gewichtGramm): int;
}

final class DhlPaket implements Versandart
{
    public function passtZu(string $land, int $g): bool { return $land === 'DE' && $g <= 31_500; }
    public function kostenCent(int $g): int { return $g <= 5_000 ? 549 : 849; }
}

final class Spedition implements Versandart
{
    public function passtZu(string $land, int $g): bool { return $g > 31_500; }
    public function kostenCent(int $g): int { return 4_900 + intdiv($g, 1_000) * 15; }
}

final class Versandrechner
{
    /** @param list<Versandart> $arten */
    public function __construct(private array $arten) {}     // haengt nur am Interface

    public function guenstigste(string $land, int $gewicht): int
    {
        $passend = array_filter($this->arten, fn (Versandart $a) => $a->passtZu($land, $gewicht));
        if ($passend === []) {
            throw new DomainException('Kein Versand moeglich');
        }
        return min(array_map(fn (Versandart $a) => $a->kostenCent($gewicht), $passend));
    }
}

// Neue Versandart? Neue Klasse - Versandrechner bleibt unveraendert (Open/Closed)
$rechner = new Versandrechner([new DhlPaket(), new Spedition()]);

m45-l2 Request-Lebenszyklus und Routing
 Jeder Request läuft durch dieselbe Kette:     public/index.php  lädt den Autoloader und  bootstrap/app.php .   Die Anwendung startet, alle  Service Provider  registrieren ihre Dienste.   Der Request passiert die globale  Middleware  (Session, CSRF, Wartungsmodus …).   Der  Router  sucht die passende Route und führt deren Middleware aus.    Controller  oder Closure erzeugen eine  Response , die rückwärts durch die Middleware zum Client geht.    Routen definierst du in  routes/web.php . Wichtige Bausteine:     Parameter :  /produkte/{produkt} , optional mit  {seite?} .    Route Model Binding : Heißt der Parameter wie ein typisiertes Model-Argument, lädt Laravel den Datensatz automatisch und liefert 404, wenn es ihn nicht gibt.    Benannte Routen :  -&gt;name('produkte.show')  und  route('produkte.show', $p)  – URLs nie hart in Templates schreiben.    Gruppen  bündeln Präfix, Middleware und Namen.    Resource-Routen :  Route::resource('produkte', …)  erzeugt die sieben REST-Routen index, create, store, show, edit, update und destroy.  
CODE
<?php
// routes/web.php
use App\Http\Controllers\ProduktController;
use App\Models\Produkt;
use Illuminate\Support\Facades\Route;

Route::get('/', fn () => view('start'))->name('start');

// Route Model Binding: {produkt} -> Produkt $produkt, 404 falls nicht vorhanden
Route::get('/produkte/{produkt}', [ProduktController::class, 'show'])
    ->name('produkte.show');

// Binding ueber eine andere Spalte als id
Route::get('/p/{produkt:slug}', [ProduktController::class, 'show']);

Route::middleware('auth')->prefix('admin')->name('admin.')->group(function () {
    Route::resource('produkte', ProduktController::class)->except(['show']);
    // admin.produkte.index, admin.produkte.store, ...
});

// Fallback fuer alles, was nicht passt
Route::fallback(fn () => response()->view('errors.404', status: 404));

m46-l1 Migrationen, Factories und Seeder
  Migrationen  sind versionierte Änderungen am Datenbankschema – Git für die Tabellenstruktur. Jede Migration hat  up()  (ausführen) und  down()  (rückgängig machen). Laravel merkt sich in der Tabelle  migrations , welche schon gelaufen sind.     php artisan make:migration create_produkte_table  legt eine neue an.    php artisan migrate  führt alle offenen aus,  migrate:rollback  nimmt den letzten Stapel zurück.    migrate:fresh --seed  löscht alles und baut neu auf –  nur lokal .    Die wichtigste Regel im Team:  Eine Migration, die schon auf einem Server lief, wird nie mehr geändert.  Änderungen kommen als neue Migration dazu. Sonst laufen die Datenbanken der Kollegen und die Produktion auseinander.    Factories  erzeugen Testdaten mit Faker,  Seeder  füllen die Datenbank damit. m46-l2 Eloquent-Models und CRUD
  Eloquent  ist das ORM von Laravel nach dem  Active-Record -Muster: Jede Model-Klasse steht für eine Tabelle, jedes Objekt für eine Zeile. Die Konventionen ersparen Konfiguration – Model  Produkt  sucht die Tabelle  produkts  (englische Pluralregel!). Bei deutschen Namen setzt du deshalb  protected $table = 'produkte'; .    Mass Assignment :  Produkt::create($request-&gt;all())  würde jedes Feld übernehmen, das ein Angreifer mitschickt – etwa  ist_admin . Deshalb verlangt Eloquent eine Erlaubnisliste in  $fillable  (oder eine Sperrliste in  $guarded ). Am sichersten ist  $request-&gt;validated() .   Mit  Casts  wandelt Eloquent Spaltenwerte automatisch: in  bool ,  datetime  (Carbon-Objekt),  array  (JSON-Spalte),  encrypted  oder in ein Enum. Seit Laravel 11 schreibt man sie als Methode  casts() .     Methode  Ergebnis      find($id)   Model oder null      findOrFail($id)   Model oder 404 (ModelNotFoundException)      where(…)-&gt;get()   Collection      where(…)-&gt;first()   erstes Model oder null      create([...])   neues Model, gespeichert      updateOrCreate([...], [...])   Upsert anhand der ersten Bedingung      $model-&gt;update([...]) ,  -&gt;delete()   ändern, löschen (bei SoftDeletes nur markieren)      Scopes  kapseln wiederkehrende Bedingungen.  Accessors  berechnen Attribute wie  $produkt-&gt;preis_formatiert . 
CODE
<?php
// app/Models/Produkt.php
namespace App\Models;

use App\Enums\ProduktStatus;
use Illuminate\Database\Eloquent\Builder;
use Illuminate\Database\Eloquent\Casts\Attribute;
use Illuminate\Database\Eloquent\Factories\HasFactory;
use Illuminate\Database\Eloquent\Model;
use Illuminate\Database\Eloquent\SoftDeletes;

class Produkt extends Model
{
    use HasFactory, SoftDeletes;

    protected $table = 'produkte';

    protected $fillable = ['kategorie_id', 'name', 'slug', 'preis_cent', 'status', 'aktiv'];

    protected function casts(): array
    {
        return [
            'aktiv'              => 'boolean',
            'status'             => ProduktStatus::class,   // Backed Enum
            'veroeffentlicht_am' => 'datetime',
        ];
    }

    // Scope: Produkt::aktiv()->get()
    public function scopeAktiv(Builder $query): void
    {
        $query->where('aktiv', true)->whereNotNull('veroeffentlicht_am');
    }

    // Accessor: $produkt->preis_formatiert
    protected function preisFormatiert(): Attribute
    {
        return Attribute::get(fn () => number_format($this->preis_cent / 100, 2, ',', '.') . ' EUR');
    }
}

// Verwendung
$p = Produkt::create(['name' => 'Kabel', 'slug' => 'kabel', 'preis_cent' => 999, 'kategorie_id' => 1]);
$p->update(['preis_cent' => 899]);
$guenstig = Produkt::aktiv()->where('preis_cent', '<', 1000)->orderBy('name')->get();


m46-l3 Beziehungen zwischen Models
 Beziehungen sind Methoden am Model, die einen Relation-Typ zurückgeben. Sie spiegeln die Kardinalitäten aus dem ER-Modell:     Kardinalität  Seite mit Fremdschlüssel  Gegenseite     1:1   belongsTo    hasOne      1:n   belongsTo  (z. B. Bestellung → Kunde)   hasMany  (Kunde → Bestellungen)     n:m  Zwischentabelle   belongsToMany  auf beiden Seiten     1:n über Zwischenmodell  –   hasManyThrough      an verschiedene Models   morphTo    morphMany  (z. B. Kommentare an Produkt und Beitrag)     Der Unterschied zwischen Methode und Eigenschaft ist wichtig:     $kunde-&gt;bestellungen()  (Methode) liefert einen  Query Builder  – du kannst weiter filtern.    $kunde-&gt;bestellungen  (Eigenschaft) lädt die Daten und liefert eine  Collection .    Bei n:m verwaltest du die Zwischentabelle mit  attach() ,  detach()  und  sync() . Zusätzliche Spalten der Zwischentabelle (Menge, Preis zum Zeitpunkt) holst du mit  withPivot() . 
CODE
<?php
class Kunde extends Model
{
    public function bestellungen(): HasMany
    {
        return $this->hasMany(Bestellung::class);
    }
}

class Bestellung extends Model
{
    public function kunde(): BelongsTo
    {
        return $this->belongsTo(Kunde::class);

    {
        return $this->belongsToMany(Produkt::class, 'bestellung_produkt')

    }
}

m46-l4 N+1-Problem, Eager Loading und Query Builder
 Das  N+1-Problem  ist der häufigste Performance-Fehler in Laravel-Projekten:    1 Abfrage lädt 50 Bestellungen.   In der Schleife löst  $bestellung-&gt;kunde-&gt;name  für  jede  Bestellung eine weitere Abfrage aus.   Ergebnis: 51 Abfragen statt 2. Bei verschachtelten Beziehungen schnell Hunderte.    Die Lösung ist  Eager Loading  mit  with() : Laravel lädt alle benötigten Kunden in  einer  zweiten Abfrage ( WHERE id IN (…) ) und verteilt sie auf die Bestellungen.     Werkzeug  Zweck      with('kunde', 'produkte')   Beziehungen vorab laden      with('produkte:id,name')   nur bestimmte Spalten laden      withCount('bestellungen')   Anzahl als  bestellungen_count , ohne Models zu laden      load('kunde')   nachträglich für eine schon geladene Collection      Model::preventLazyLoading()   wirft bei vergessenem Eager Loading eine Exception     Für Auswertungen ist der  Query Builder  ( DB::table() ) oft besser als Eloquent: Er erzeugt keine Model-Objekte und ist dadurch bei großen Mengen viel sparsamer. Mehrere zusammengehörige Schreibvorgänge umschließt du mit  DB::transaction() . Wirft die Closure, wird automatisch zurückgerollt. 
CODE
<?php
// FALSCH: 1 + N Abfragen
$bestellungen = Bestellung::latest()->take(50)->get();
foreach ($bestellungen as $b) {
    echo $b->kunde->name;              // jedes Mal SELECT * FROM kunden WHERE id = ?
}

// RICHTIG: 2 Abfragen
$bestellungen = Bestellung::with('kunde:id,name')
    ->withCount('produkte')
    ->latest()
    ->take(50)
    ->get();

// app/Providers/AppServiceProvider.php - Lazy Loading lokal verbieten
public function boot(): void
{
    Model::preventLazyLoading(! $this->app->isProduction());
}

// Auswertung mit dem Query Builder - keine Model-Objekte
$umsatzProMonat = DB::table('bestellungen')
    ->selectRaw("DATE_FORMAT(created_at, '%Y-%m') AS monat, SUM(summe_cent) AS umsatz")
    ->where('status', 'bezahlt')
    ->groupBy('monat')
    ->orderBy('monat')
    ->get();

// Grosse Mengen in Haeppchen verarbeiten
Produkt::where('aktiv', false)->chunkById(500, function ($produkte) {
    foreach ($produkte as $p) { /* ... */ }
});

// Transaktion
DB::transaction(function () use ($kunde, $warenkorb) {
    $bestellung = $kunde->bestellungen()->create(['status' => 'offen']);
    foreach ($warenkorb as $pos) {
        $bestellung->produkte()->attach($pos['id'], ['menge' => $pos['menge']]);
        Produkt::whereKey($pos['id'])->decrement('bestand', $pos['menge']);
    }
});


m47-l1 Validierung und Form Requests
 Laravel validiert Eingaben mit Regeln.  $request-&gt;validate([...])  prüft und liefert  nur die validierten Felder  zurück. Schlägt die Prüfung fehl, reagiert Laravel passend zur Anfrage:     Browser-Formular : Redirect zurück, Fehler und alte Eingaben stehen in der Session ( @error ,  old() ).    JSON-Anfrage  (Header  Accept: application/json ): Antwort  422  mit den Fehlern als JSON.    Häufige Regeln:  required ,  nullable ,  string ,  integer ,  email ,  max:255 ,  min:8 ,  in:a,b ,  unique:users,email ,  exists:kategorien,id ,  date ,  after:today ,  confirmed  (Feld plus  _confirmation ),  image ,  mimes:pdf,jpg . Für Regeln mit Objekten gibt es Klassen wie  Rule::unique(…)-&gt;ignore($id) ,  Rule::enum(Status::class)  und  Password::min(12) .   Ab einer Handvoll Regeln lagerst du sie in einen  Form Request  aus ( php artisan make:request ). Er bündelt  authorize()  und  rules()  und wird einfach als Parametertyp in den Controller geschrieben – Laravel validiert, bevor deine Methode überhaupt läuft. 
CODE
<?php
// app/Http/Requests/ProduktSpeichernRequest.php
namespace App\Http\Requests;

use App\Enums\ProduktStatus;
use Illuminate\Foundation\Http\FormRequest;
use Illuminate\Validation\Rule;

class ProduktSpeichernRequest extends FormRequest
{
    public function authorize(): bool
    {
        return $this->user()->can('create', \App\Models\Produkt::class);
    }

    public function rules(): array
    {
        return [
            'name'         => ['required', 'string', 'max:255'],
            'slug'         => ['required', 'alpha_dash', Rule::unique('produkte', 'slug')->ignore($this->route('produkt'))],
            'preis_cent'   => ['required', 'integer', 'min:0'],
            'kategorie_id' => ['required', 'exists:kategorien,id'],
            'status'       => ['required', Rule::enum(ProduktStatus::class)],
            'bild'         => ['nullable', 'image', 'max:2048'],   // KB
        ];
    }

    public function messages(): array
    {
        return ['slug.unique' => 'Diese URL ist schon vergeben.'];
    }
}

// Controller - validiert ist es hier schon
public function store(ProduktSpeichernRequest $request): RedirectResponse
{
    $produkt = Produkt::create($request->validated());
    return to_route('produkte.show', $produkt)->with('status', 'Gespeichert.');
}


m47-l2 Authentifizierung, Middleware und CSRF
 Laravel liefert die Bausteine für Login und Sessions mit. Fertige Oberflächen inklusive Registrierung, Passwort-Reset und E-Mail-Bestätigung bekommst du über die offiziellen  Starter Kits  (Livewire, React oder Vue). In älteren Projekten heißen sie  Breeze  oder  Jetstream .     Auth::attempt($credentials)  prüft Zugangsdaten und loggt ein.    auth()-&gt;user()  bzw.  $request-&gt;user()  liefert den eingeloggten Benutzer.   Die Middleware  auth  schützt Routen,  guest  ist das Gegenstück,  verified  verlangt eine bestätigte E-Mail.     Middleware  sind Filter um den Request: Sie können ihn abweisen, verändern oder die Antwort anpassen. Eigene legst du mit  make:middleware  an und registrierst sie in  bootstrap/app.php .    CSRF  (Cross-Site Request Forgery): Eine fremde Seite bringt den Browser des eingeloggten Opfers dazu, ein Formular an deine Anwendung zu senden. Der Browser schickt das Session-Cookie mit. Laravel verlangt deshalb bei jedem POST, PUT, PATCH und DELETE ein geheimes Token, das nur deine eigenen Seiten kennen. In Blade-Formularen genügt  @csrf . Webhooks von Zahlungsanbietern nimmst du gezielt aus und prüfst stattdessen deren Signatur. 
CODE
<?php
// app/Http/Middleware/NurAdmins.php
namespace App\Http\Middleware;

use Closure;
use Illuminate\Http\Request;
use Symfony\Component\HttpFoundation\Response;

class NurAdmins
{
    public function handle(Request $request, Closure $next): Response
    {
        if (! $request->user()?->ist_admin) {
            abort(403);
        }
        return $next($request);          // weiter zur naechsten Schicht
    }
}

// bootstrap/app.php
->withMiddleware(function (Middleware $middleware) {
    $middleware->alias(['admin' => \App\Http\Middleware\NurAdmins::class]);
    $middleware->validateCsrfTokens(except: ['webhooks/stripe']);
})

// routes/web.php
Route::middleware(['auth', 'verified', 'admin'])->group(function () {
    Route::get('/admin', AdminDashboardController::class);
});

// Login von Hand (die Starter Kits machen das fuer dich)
if (Auth::attempt($request->only('email', 'password'), $request->boolean('remember'))) {
    $request->session()->regenerate();
    return redirect()->intended('/dashboard');
}


m47-l3 Autorisierung mit Gates und Policies
 Authentifizierung beantwortet „Wer bist du?“,  Autorisierung  „Darfst du das?“. Die häufigste Lücke in Webanwendungen (OWASP-Platz 1,  Broken Access Control ) ist eine fehlende Prüfung: Wer  /rechnungen/4711  aufruft, sieht die Rechnung – auch wenn sie einem anderen Kunden gehört.    Policies  bündeln die Regeln für ein Model in einer Klasse ( make:policy ProduktPolicy --model=Produkt ). Jede Methode bekommt den Benutzer und gegebenenfalls das Model und liefert  true  oder  false . Laravel findet  ProduktPolicy  zu  Produkt  automatisch.     Ort  Prüfung     Controller   Gate::authorize('update', $produkt);  → 403 bei Ablehnung     Route   -&gt;can('update', 'produkt')      Form Request   authorize()  mit  $this-&gt;user()-&gt;can(…)      Blade   @can('update', $produkt) … @endcan      beliebig   $user-&gt;can('delete', $produkt)      Die Methode  before()  in einer Policy läuft vor allen anderen – praktisch für Administratoren. Für Prüfungen ohne Model (etwa „darf das Dashboard sehen“) gibt es  Gates  als einfache Closures.   Ein Detail aus der Praxis: Bei fremden Datensätzen lieber  404 statt 403  liefern ( Response::denyAsNotFound() ). So verrät die Antwort nicht, dass Rechnung 4711 existiert. 
CODE
<?php
// app/Policies/BestellungPolicy.php
namespace App\Policies;

use App\Models\Bestellung;
use App\Models\User;
use Illuminate\Auth\Access\Response;

class BestellungPolicy
{
    public function before(User $user): ?bool
    {
        return $user->ist_admin ? true : null;   // null = normale Pruefung
    }

    public function view(User $user, Bestellung $bestellung): Response
    {
        return $user->id === $bestellung->kunde->user_id
            ? Response::allow()
            : Response::denyAsNotFound();
    }

    public function cancel(User $user, Bestellung $bestellung): bool
    {
        return $user->id === $bestellung->kunde->user_id
            && $bestellung->status === BestellStatus::Offen;
    }
}

// Controller
public function show(Bestellung $bestellung): View
{
    Gate::authorize('view', $bestellung);
    return view('bestellungen.show', compact('bestellung'));
}

// Gate ohne Model - AppServiceProvider::boot()
Gate::define('berichte-sehen', fn (User $user) => $user->rolle === 'controlling');


m56-l1 Blade-Komponenten bauen
 Komponenten sind wiederverwendbare Bausteine für Oberflächen: Buttons, Hinweisboxen, Formularfelder, Karten. Statt dasselbe HTML in zwanzig Views zu kopieren, schreibst du es einmal und nutzt es als  &lt;x-name&gt; .     Art  Datei  Wann     anonyme Komponente  nur  resources/views/components/hinweis.blade.php   reine Darstellung, wenig Logik     Klassen-Komponente  Klasse in  app/View/Components  plus View ( make:component )  braucht Daten aus Services oder Berechnungen     In anonymen Komponenten deklarierst du die erwarteten Werte mit  @props . Alle weiteren HTML-Attribute (zum Beispiel  class  oder  id ) landen im Objekt  $attributes . Mit  $attributes-&gt;merge(['class' =&gt; '…'])  ergänzt du Standardklassen, ohne dass der Aufrufer sie überschreibt.   Werte übergibst du als Attribut:  typ="warnung"  übergibt den String „warnung“,  :anzahl="$offen"  (mit Doppelpunkt) einen PHP-Ausdruck. Der Inhalt zwischen den Tags landet in  $slot , weitere Bereiche in benannten Slots wie  &lt;x-slot:titel&gt; .   Probier es aus  Baue eine Komponente  &lt;x-preis :cent="1999" /&gt; , die „19,99 €“ ausgibt, und eine Komponente  &lt;x-karte&gt;  mit einem benannten Slot für den Titel.  
CODE
{{-- resources/views/components/hinweis.blade.php --}}
@props(['typ' => 'info', 'titel' => null])

    $farben = [
        'info'     => 'border-blue-500 bg-blue-50',
        'erfolg'   => 'border-green-600 bg-green-50',
        'warnung'  => 'border-amber-500 bg-amber-50',
    ];
@endphp

<div {{ $attributes->merge(['class' => 'rounded border-l-4 p-4 ' . ($farben[$typ] ?? $farben['info'])]) }} role="status">
    @if ($titel)
        <p class="font-semibold">{{ $titel }}</p>
    @endif

m56-l3 Livewire: interaktiv ohne eigenes JavaScript
  Livewire  macht Blade-Oberflächen interaktiv, ohne dass du ein JavaScript-Framework schreiben musst. <?php
// app/Livewire/ProduktSuche.php
namespace App\Livewire;

use App\Models\Produkt;
use Livewire\Component;

class ProduktSuche extends Component
{
    public string $suche = '';
    public bool $nurLieferbar = false;

    public function zuruecksetzen(): void
    {
        $this->reset('suche', 'nurLieferbar');
    }

    public function render()
    {
        $produkte = Produkt::query()
            ->when($this->suche !== '', fn ($q) => $q->where('name', 'like', '%' . $this->suche . '%'))
            ->when($this->nurLieferbar, fn ($q) => $q->where('bestand', '>', 0))
            ->orderBy('name')
            ->limit(20)
            ->get();

        return view('livewire.produkt-suche', compact('produkte'));
    }
}

m57-l1 Datei-Uploads und das Storage-System
 Laravel abstrahiert Speicherorte über  Disks :  local  (privat,  storage/app/private ),  public  (öffentlich über  storage/app/public ) und Cloud-Speicher wie  s3 . Dein Code spricht nur mit  Storage::disk('…')  – der Wechsel vom lokalen Ordner zu S3 ist eine Änderung in der Konfiguration.    Validieren:  ['bild' =&gt; ['required', 'image', 'max:2048']]  (Größe in KB) oder lesbarer mit  File::image()-&gt;max('2mb') .   Speichern:  $request-&gt;file('bild')-&gt;store('avatare', 'public')  vergibt einen zufälligen Namen und liefert den Pfad zurück, den du in der Datenbank ablegst.   Öffentlich zugänglich machen: einmal  php artisan storage:link , danach  Storage::url($pfad) .     Private Dateien  (Rechnungen, Verträge) gehören nie auf die öffentliche Disk. Sie werden über eine Route ausgeliefert, die vorher die Berechtigung prüft, oder über eine zeitlich begrenzte URL ( temporaryUrl , bei S3).   Typischer Fehler  Den Originalnamen der hochgeladenen Datei zu übernehmen ( getClientOriginalName() ) ist riskant: Er kann Pfadanteile oder gefährliche Endungen enthalten und kollidiert mit gleichnamigen Dateien. Laravel vergibt mit  store()  deshalb einen zufälligen Namen.  
CODE
<?php
// app/Http/Controllers/AvatarController.php
use Illuminate\Http\Request;
use Illuminate\Support\Facades\Storage;
use Illuminate\Validation\Rule;
use Illuminate\Validation\Rules\File;

public function update(Request $request)
{
    $request->validate([
        'avatar' => ['required', File::image()->max('2mb')->dimensions(Rule::dimensions()->maxWidth(2000))],
    ]);

    $user = $request->user();
    $alt  = $user->avatar_pfad;

    $user->update(['avatar_pfad' => $request->file('avatar')->store('avatare', 'public')]);

    if ($alt) {
        Storage::disk('public')->delete($alt);      // alte Datei aufraeumen
    }

    return back()->with('status', 'Profilbild aktualisiert.');
}

// Private Rechnung: Auslieferung nur nach Pruefung
public function rechnung(Bestellung $bestellung)
{
    Gate::authorize('view', $bestellung);
    return Storage::disk('local')->download($bestellung->rechnung_pfad, "Rechnung-{$bestellung->id}.pdf");
}


m57-l2 E-Mails mit Mailables
 Jede E-Mail ist in Laravel eine eigene Klasse, ein  Mailable  ( php artisan make:mail BestellBestaetigung --markdown=mail.bestellung ). Seit Laravel 10 beschreibt man sie mit drei Methoden:     envelope()  – Betreff, Absender, Antwortadresse.    content()  – welche View, mit welchen Daten.    attachments()  – Anhänge, z. B. die Rechnung als PDF.    Öffentliche Eigenschaften des Mailables stehen in der View automatisch zur Verfügung. Markdown-Mails nutzen fertige Bausteine wie  &lt;x-mail::button&gt;  und  &lt;x-mail::table&gt;  und sehen in allen Mailprogrammen ordentlich aus.   Verschickt wird mit  Mail::to($kunde)-&gt;send(...) . Weil der Versand Sekunden dauern kann, schickst du Mails im Produktivbetrieb mit  -&gt;queue(...)  über die Warteschlange.   Lokal sollen keine echten Mails rausgehen. Mit  MAIL_MAILER=log  landen sie im Log; bequemer ist ein lokales Postfach wie  Mailpit , das alle Mails abfängt und im Browser anzeigt. 
CODE
<?php
// app/Mail/BestellBestaetigung.php
namespace App\Mail;

use App\Models\Bestellung;
use Illuminate\Bus\Queueable;
use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Mail\Attachment;
use Illuminate\Mail\Mailable;
use Illuminate\Mail\Mailables\Content;
use Illuminate\Mail\Mailables\Envelope;
use Illuminate\Queue\SerializesModels;

class BestellBestaetigung extends Mailable implements ShouldQueue
{
    use Queueable, SerializesModels;

    public function __construct(public Bestellung $bestellung) {}

    public function envelope(): Envelope
    {
        return new Envelope(subject: "Deine Bestellung #{$this->bestellung->id}");
    }

    public function content(): Content
    {
        return new Content(markdown: 'mail.bestellung');
    }

    public function attachments(): array
    {
        return [Attachment::fromStorageDisk('local', $this->bestellung->rechnung_pfad)->as('Rechnung.pdf')];
    }
}

// Versand
Mail::to($bestellung->kunde->email)->send(new BestellBestaetigung($bestellung));   // ShouldQueue -> landet in der Queue


m57-l3 Benachrichtigungen über mehrere Kanäle

Welche Kanäle es sind, entscheidet die Methode  via()  – auch abhängig von den Einstellungen des Benutzers.     toMail()  baut die E-Mail,  toArray()  die Daten für den Datenbankkanal. <?php
// app/Notifications/BestellungVersendet.php
namespace App\Notifications;

use App\Models\Bestellung;

use Illuminate\Contracts\Queue\ShouldQueue;
use Illuminate\Notifications\Messages\MailMessage;
use Illuminate\Notifications\Notification;

class BestellungVersendet extends Notification implements ShouldQueue
{
    use Queueable;

    public function __construct(public Bestellung $bestellung) {}

    public function via(object $notifiable): array
    {
        return $notifiable->mails_erwuenscht ? ['mail', 'database'] : ['database'];
    }

    public function toMail(object $notifiable): MailMessage
    {
        return (new MailMessage)
            ->subject('Deine Bestellung ist unterwegs')

    }

    public function toArray(object $notifiable): array
    {
        return ['bestellung_id' => $this->bestellung->id, 'text' => 'Bestellung versendet'];
    }
}

        return $this->hasMany(Bestellung::class);

    public function letzteBestellung(): HasOne
    {
        return $this->hasOne(Bestellung::class)->latestOfMany();

}

    ->withCount('bestellungen')

    ->orderByDesc('bestellungen_sum_summe_cent')

m58-l2 Eigene Casts und Value Objects
 Mit Casts wandelt Eloquent Spaltenwerte automatisch. Die eingebauten ( boolean ,  datetime ,  array ,  encrypted , Enums) decken viel ab. Für eigene Fachtypen schreibst du einen  Custom Cast : eine Klasse mit  get()  (Datenbank → PHP) und  set()  (PHP → Datenbank).   Ein Klassiker ist Geld: In der Datenbank liegt ein Integer in Cent, im Code soll es ein  Geld -Objekt sein, das rechnen und formatieren kann. Der Cast sorgt dafür, dass niemand mehr versehentlich Euro und Cent verwechselt.     php artisan make:cast GeldCast  erzeugt das Gerüst.   Im Model:  'preis' =&gt; GeldCast::class  in  casts() .   Für verschlüsselte Spalten gibt es  encrypted ,  encrypted:array  und  encrypted:collection  – der Schlüssel ist  APP_KEY .    Accessors mit  Attribute::make(get: …, set: …)  reichen für einfache Umformungen. Ein Cast lohnt sich, sobald derselbe Fachtyp in mehreren Models vorkommt. 
CODE
<?php
// app/Casts/GeldCast.php
namespace App\Casts;

use App\Support\Geld;
use Illuminate\Contracts\Database\Eloquent\CastsAttributes;
use Illuminate\Database\Eloquent\Model;
use InvalidArgumentException;

class GeldCast implements CastsAttributes
{
    public function get(Model $model, string $key, mixed $value, array $attributes): ?Geld
    {
        return $value === null ? null : Geld::cent((int) $value);
    }

    public function set(Model $model, string $key, mixed $value, array $attributes): ?int
    {
        if ($value === null) {
            return null;
        }
        if (!$value instanceof Geld) {
            throw new InvalidArgumentException("$key muss ein Geld-Objekt sein.");
        }
        return $value->cent;
    }
}

// Model
protected function casts(): array
{
    return [
        'preis'        => GeldCast::class,
        'iban'         => 'encrypted',          // verschluesselt in der Datenbank
        'einstellungen' => 'array',
    ];
}

// Verwendung
$produkt->preis = Geld::euro(19.99);
echo $produkt->preis->plus(Geld::euro(5))->format();   // 24,99 EUR


m58-l3 Polymorphe Beziehungen
 Manchmal gehört ein Datensatz zu  verschiedenen  Arten von Models: Kommentare an Produkten und an Blogbeiträgen, Bilder an Kategorien und an Benutzern. Statt für jede Kombination eine eigene Tabelle zu bauen, nutzt man eine  polymorphe Beziehung .    Die Tabelle  kommentare  bekommt zwei Spalten:  kommentierbar_id  und  kommentierbar_type .   In der Migration erzeugt  $table-&gt;morphs('kommentierbar')  beide Spalten plus Index.   Das Model  Kommentar  hat  morphTo() , Produkt und Beitrag haben  morphMany(Kommentar::class, 'kommentierbar') .    Standardmäßig steht in der  _type -Spalte der volle Klassenname, etwa  App\Models\Produkt . Benennst du die Klasse später um, passen alte Daten nicht mehr. Mit einer  Morph Map  speicherst du stattdessen kurze, stabile Namen wie  produkt .  Relation::enforceMorphMap()  erzwingt das für alle polymorphen Beziehungen.   Der Preis der Flexibilität: Die Datenbank kann für  kommentierbar_id  keinen echten Fremdschlüssel prüfen, weil die Zieltabelle wechselt. Aufräumen beim Löschen musst du selbst übernehmen, etwa in einem  deleting -Event. 
CODE
<?php
// Migration
Schema::create('kommentare', function (Blueprint $table) {
    $table->id();
    $table->morphs('kommentierbar');          // kommentierbar_id + kommentierbar_type + Index
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->text('text');
    $table->timestamps();
});

// Models
class Kommentar extends Model
{
    protected $table = 'kommentare';

    public function kommentierbar(): MorphTo
    {
        return $this->morphTo();
    }
}

class Produkt extends Model
{
    public function kommentare(): MorphMany
    {
        return $this->morphMany(Kommentar::class, 'kommentierbar');
    }
}

// AppServiceProvider::boot() - stabile Namen statt Klassennamen
Relation::enforceMorphMap([
    'produkt' => Produkt::class,
    'beitrag' => Beitrag::class,
]);

// Verwendung
$produkt->kommentare()->create(['user_id' => $user->id, 'text' => 'Top Kabel!']);
$k = Kommentar::with('kommentierbar')->latest()->first();
echo $k->kommentierbar::class;                // App\Models\Produkt


m58-l4 Globale Scopes, Soft Deletes und Pruning
 Ein  globaler Scope  hängt an jede Abfrage eines Models automatisch eine Bedingung an. Soft Deletes sind selbst ein Beispiel: Der Trait  SoftDeletes  registriert einen Scope, der  deleted_at IS NULL  ergänzt.    Eigene globale Scopes eignen sich für Regeln, die  immer  gelten, etwa „nur Datensätze des aktuellen Mandanten“.   Ausnahmen machst du mit  withoutGlobalScope(...) , bei Soft Deletes mit  withTrashed()  oder  onlyTrashed() .    Daten, die nicht ewig liegen dürfen – alte Warenkörbe, abgelaufene Tokens, Logs nach Ablauf der Aufbewahrungsfrist – räumt  Pruning  auf. Das Model bekommt den Trait  Prunable  und eine Methode  prunable() , die beschreibt, was weg darf. Der Scheduler ruft dann regelmäßig  model:prune  auf.   Das hat auch eine rechtliche Seite: Die DSGVO verlangt Speicherbegrenzung. Pruning ist die technische Umsetzung von Löschfristen.   Typischer Fehler  Ein globaler Scope ist unsichtbar. Wer  Produkt::count()  schreibt und sich über ein zu kleines Ergebnis wundert, hat den Scope vergessen. Setze globale Scopes deshalb sparsam ein und dokumentiere sie im Model.  
CODE
<?php
// Mandantentrennung als globaler Scope
#[ScopedBy(MandantScope::class)]
class Rechnung extends Model
{
    use SoftDeletes, MassPrunable;

    // Pruning: Rechnungen 10 Jahre nach Jahresende loeschen (Aufbewahrungsfrist)
    public function prunable(): Builder
    {
        return static::onlyTrashed()->where('deleted_at', '<', now()->subYears(10)->endOfYear());
    }
}

class MandantScope implements Scope
{
    public function apply(Builder $builder, Model $model): void
    {
        $builder->where($model->getTable() . '.mandant_id', auth()->user()?->mandant_id);
    }
}

// routes/console.php
Schedule::command('model:prune')->daily();

// Ausnahmen bewusst und sichtbar
Rechnung::withoutGlobalScope(MandantScope::class)->count();   // alle Mandanten (Admin-Report)
Rechnung::withTrashed()->find($id);                            // auch geloeschte


m48-l1 API-Routen, Ressourcen und Statuscodes
 Für eine JSON-API richtest du mit  php artisan install:api  die Datei  routes/api.php  ein (Präfix  /api , keine Session, kein CSRF) und installierst gleichzeitig  Sanctum  für Tokens.  Route::apiResource()  erzeugt die fünf Routen index, store, show, update und destroy.   Gib Models  nie direkt  als JSON zurück. Sonst landet jede neue Datenbankspalte automatisch in der API – auch  passwort_hash  oder interne Notizen.  API Resources  ( make:resource ) legen genau fest, welche Felder in welchem Format herausgehen.  whenLoaded()  bindet Beziehungen nur ein, wenn sie per Eager Loading geladen wurden, und verhindert so N+1 in der API.     Status  Bedeutung  Typischer Fall     200 OK  Erfolg mit Inhalt  GET, PUT     201 Created  angelegt  POST, mit  Location -Header     204 No Content  Erfolg ohne Inhalt  DELETE     401 Unauthorized  nicht angemeldet  Token fehlt oder ungültig     403 Forbidden  angemeldet, aber nicht berechtigt  Policy lehnt ab     404 Not Found  Ressource unbekannt  Route Model Binding     422 Unprocessable  Validierung fehlgeschlagen  Form Request     429 Too Many Requests  Rate Limit erreicht   throttle       paginate()  an einer Resource-Collection liefert die Daten automatisch mit  links  und  meta  (aktuelle Seite, Gesamtzahl). Für sehr große Tabellen ist  cursorPaginate()  schneller, weil es kein  OFFSET  braucht. 
CODE
<?php
// routes/api.php
Route::middleware('auth:sanctum')->prefix('v1')->group(function () {
    Route::apiResource('produkte', Api\ProduktController::class);
});

// app/Http/Resources/ProduktResource.php
class ProduktResource extends JsonResource
{
    public function toArray(Request $request): array
    {
        return [
            'id'        => $this->id,
            'name'      => $this->name,
            'preis'     => ['cent' => $this->preis_cent, 'waehrung' => 'EUR'],
            'status'    => $this->status->value,
            'kategorie' => new KategorieResource($this->whenLoaded('kategorie')),
            'erstellt'  => $this->created_at->toIso8601String(),
        ];
    }
}

// app/Http/Controllers/Api/ProduktController.php
class ProduktController extends Controller
{
    public function index()
    {
        return ProduktResource::collection(
            Produkt::with('kategorie')->aktiv()->paginate(25)
        );
    }

    public function store(ProduktSpeichernRequest $request)
    {
        $produkt = Produkt::create($request->validated());

        return (new ProduktResource($produkt))
            ->response()
            ->setStatusCode(201)
            ->header('Location', route('produkte.show', $produkt));
    }

    public function destroy(Produkt $produkt)
    {
        Gate::authorize('delete', $produkt);

m48-l2 Token-Authentifizierung mit Sanctum
  Laravel Sanctum  deckt zwei Fälle ab:     API-Tokens  für mobile Apps, Skripte und Fremdsysteme. Der Client schickt  Authorization: Bearer &lt;token&gt; .    SPA-Authentifizierung  für dein eigenes JavaScript-Frontend auf derselben Domain. Das läuft über das normale Session-Cookie mit CSRF-Schutz – ohne Token im JavaScript, das durch XSS gestohlen werden könnte.    Tokens werden in der Tabelle  personal_access_tokens  nur als  SHA-256-Hash  gespeichert. Den Klartext siehst du genau einmal, direkt nach  createToken() . Danach kann ihn niemand mehr auslesen, auch du nicht.    Abilities  begrenzen, was ein Token darf ( produkte:lesen ). Gib jedem Token nur die Rechte, die der Client wirklich braucht, und setze ein Ablaufdatum. Die Abilities ersetzen keine Policy: Ein Token mit  produkte:schreiben  darf trotzdem nur  eigene  Produkte ändern.   Brauchst du einen vollständigen OAuth2-Server, also Drittanbieter-Apps mit Zustimmungsdialog, ist  Laravel Passport  das passende Paket. Für die meisten Projekte reicht Sanctum.

<?php
// Token ausstellen - z. B. in einem Login-Endpunkt fuer die Mobile-App
Route::post('/v1/tokens', function (Request $request) {
    $daten = $request->validate([
        'email'    => ['required', 'email'],
        'password' => ['required'],
        'geraet'   => ['required', 'string', 'max:100'],

    $user = User::where('email', $daten['email'])->first();

        $daten['geraet'],
        ['produkte:lesen', 'bestellungen:anlegen'],

})->middleware('throttle:5,1');                    // 5 Versuche pro Minute

// Ability pruefen - die Aliase 'abilities' und 'ability' vorher in
// bootstrap/app.php registrieren (Laravel\Sanctum\Http\Middleware\CheckAbilities ...)
Route::middleware(['auth:sanctum', 'abilities:bestellungen:anlegen'])
    ->post('/v1/bestellungen', [BestellungController::class, 'store']);

// Token widerrufen (Logout auf diesem Geraet)
$request->user()->currentAccessToken()->delete();


m48-l3 Rate Limiting, Fehlerformat und Idempotenz
 Eine produktionsreife API braucht mehr als funktionierende Endpunkte:     Rate Limiting  schützt vor Missbrauch und Überlast. Benannte Limiter definierst du in  AppServiceProvider::boot()  mit  RateLimiter::for() , die Route nutzt sie über  throttle:name . Laravel liefert  429  und die Header  Retry-After  und  X-RateLimit-Remaining .    Einheitliches Fehlerformat : Clients sollen Fehler maschinell verarbeiten können. In  bootstrap/app.php  kannst du im Abschnitt  withExceptions()  steuern, wie Exceptions als JSON gerendert werden. Mit  APP_DEBUG=false  erscheinen dabei nie Stacktraces.    Idempotenz : Netzwerke verlieren Antworten. Der Client weiß dann nicht, ob die Bestellung angelegt wurde, und sendet erneut. GET, PUT und DELETE sind von Natur aus idempotent, POST nicht. Die Lösung ist ein  Idempotency-Key -Header: Der Server merkt sich den Schlüssel und liefert beim zweiten Mal die erste Antwort, statt doppelt zu buchen.    Für die Dokumentation erzeugen Pakete wie  Scramble  eine OpenAPI-Beschreibung direkt aus Routen, Form Requests und Resources. Sie bleibt dadurch automatisch aktuell. 
CODE
<?php
// app/Providers/AppServiceProvider.php
public function boot(): void
{
    RateLimiter::for('api', function (Request $request) {
        return $request->user()
            ? Limit::perMinute(120)->by($request->user()->id)
            : Limit::perMinute(20)->by($request->ip());
    });
}

// bootstrap/app.php - einheitliches Fehlerformat fuer die API
->withExceptions(function (Exceptions $exceptions) {
    // FachlicherKonflikt: gemeinsame Basisklasse, z. B. fuer
    // UngueltigerStatuswechsel und LagerbestandZuNiedrig
    $exceptions->render(function (FachlicherKonflikt $e, Request $request) {
        if ($request->is('api/*')) {
            return response()->json([
                'fehler' => ['code' => Str::snake(class_basename($e)), 'nachricht' => $e->getMessage()],
            ], 409);
        }
    });
})

// Idempotenz bei POST /api/v1/bestellungen
public function store(BestellungRequest $request, BestellungAnlegen $anlegen)
{
    $schluessel = $request->header('Idempotency-Key');
    abort_unless($schluessel, 400, 'Idempotency-Key fehlt.');
    $schluessel = "idem:{$request->user()->id}:{$schluessel}";   // pro Benutzer

    $bestellungId = Cache::lock("{$schluessel}:lock", 10)->block(5, function () use ($request, $anlegen, $schluessel) {
        // Zweiter Aufruf mit gleichem Schluessel: liefert die ID der ersten Bestellung
        return Cache::remember($schluessel, now()->addDay(),
            fn () => $anlegen->ausfuehren($request->user(), $request->positionen())->id);
    });

    return (new BestellungResource(Bestellung::findOrFail($bestellungId)))
        ->response()
        ->setStatusCode(201);
}


m49-l1 Service Container und Dependency Injection
 Der  Service Container  ist das Herz von Laravel. Er weiß, wie man Objekte baut, und liefert sie dort, wo sie gebraucht werden –  Dependency Injection . Eine Klasse holt sich ihre Abhängigkeiten nicht selbst ( new StripeClient(...) ), sondern bekommt sie im Konstruktor.     Auto-Wiring : Konkrete Klassen ohne skalare Parameter baut der Container per Reflection selbst. Du musst nichts registrieren.    Interfaces  brauchen eine  Bindung : welches Interface zu welcher Implementierung.    bind()  erzeugt bei jeder Anfrage ein neues Objekt,  singleton()  eins pro Anwendung bzw. Request,  scoped()  eins pro Request, auch unter Octane oder in Queue-Workern.    Kontextuelle Bindung :  when(A::class)-&gt;needs(I::class)-&gt;give(B::class) .    Injiziert wird überall, wo Laravel Objekte erzeugt: Controller (Konstruktor und Methoden), Jobs ( handle() ), Listener, Commands, Middleware. Manuell geht es mit  app(Klasse::class) .   Der eigentliche Gewinn zeigt sich im Test: Du tauschst die echte Implementierung gegen eine Attrappe aus, ohne den Code zu ändern, der sie benutzt.

<?php
interface Wechselkurse
{
    public function kurs(string $von, string $nach): float;

{

// Controller - PreisRechner wird mitsamt Abhaengigkeiten gebaut

m49-l2 Service Provider und Facades
  Service Provider  sind der Ort, an dem die Anwendung zusammengesetzt wird. Jeder hat zwei Phasen:     register()  –  nur  Bindungen in den Container eintragen. Andere Dienste sind hier eventuell noch nicht verfügbar.    boot()  – läuft, nachdem  alle  Provider registriert sind. Hier konfigurierst du Rate Limiter, Gates, Observer, Macros und Model-Einstellungen.    Eigene Provider legst du mit  make:provider  an. Sie landen in  bootstrap/providers.php .    Facades  wie  Cache::get()  sehen aus wie statische Aufrufe, sind aber keine. Jede Facade leitet den Aufruf an ein Objekt aus dem Container weiter:  Cache::get('x')  entspricht  app('cache')-&gt;get('x') . Dadurch bleiben sie testbar, denn  Cache::shouldReceive()  oder  Mail::fake()  tauschen das Objekt dahinter aus.     Variante  Beispiel  Stärke     Facade   Cache::get('k')   kurz, gut lesbar, fakebar     Helper   cache('k')   noch kürzer     Injektion   __construct(CacheRepository $cache)   Abhängigkeit sichtbar im Konstruktor     In Controllern und Laravel-nahem Code sind Facades üblich. In Fachlogik, die du auch ohne Laravel denken willst, ist Konstruktor-Injektion die klarere Wahl.

<?php
// app/Providers/ShopServiceProvider.php

    public function boot(): void
    {
        Model::shouldBeStrict(! $this->app->isProduction());  // Lazy Loading u. a. melden

m49-l3 Events, Listener und Observer
  Events  entkoppeln „etwas ist passiert“ von „was daraufhin passieren soll“. Der Code, der eine Bestellung anlegt, löst  BestellungAufgegeben  aus. Ob danach eine Mail verschickt, das Lager benachrichtigt und eine Statistik aktualisiert wird, entscheiden die  Listener . Ein neuer Listener ändert den bestehenden Code nicht.     make:event  und  make:listener  erzeugen die Klassen. Laravel findet Listener automatisch über den Typ-Hint in  handle() .   Listener mit  implements ShouldQueue  laufen im Hintergrund über die Queue.    ShouldDispatchAfterCommit  am Event (oder  $afterCommit  am Listener) sorgt dafür, dass erst nach erfolgreichem Datenbank-Commit verarbeitet wird.     Observer  reagieren auf Model-Lebenszyklus-Ereignisse:  creating ,  created ,  updating ,  updated ,  deleting ,  deleted  und weitere. Typische Aufgaben sind das Setzen von Slugs oder das Leeren von Caches.   Aber Vorsicht: Observer sind  unsichtbar . Wer  $bestellung-&gt;save()  liest, sieht nicht, dass dabei Mails verschickt werden. Und Massenoperationen wie  Produkt::where(…)-&gt;update([...])  lösen  keine  Model-Events aus. m49-l4 Schlanke Controller: Actions und Services
 Mit dem Projekt wächst die Frage:  Wo gehört die Geschäftslogik hin?  Steht sie im Controller, kann sie weder ein Artisan-Command noch ein Job noch die API wiederverwenden. Ein bewährtes Muster sind  Action-Klassen : eine Klasse pro Anwendungsfall mit einer öffentlichen Methode.    Der  Controller  übersetzt HTTP in einen Aufruf und das Ergebnis zurück in HTTP.   Die  Action  enthält den Anwendungsfall: Transaktion, Prüfungen, Speichern, Event auslösen.    Models  kennen ihre eigenen Regeln (Statusübergänge, Berechnungen am eigenen Datensatz).    Für die Übergabe vieler Werte eignen sich  DTOs  (Data Transfer Objects): kleine readonly-Klassen statt loser Arrays. Die IDE kennt dann die Felder, und Tippfehler fallen sofort auf.   Übertreib es nicht. Für ein einfaches CRUD-Formular ist  Produkt::create($request-&gt;validated())  im Controller völlig in Ordnung. Schichten lohnen sich dort, wo Logik wiederverwendet wird oder komplex genug ist, um eigene Tests zu verdienen. Nach Fachbereichen geordnete Ordner ( app/Bestellwesen ,  app/Katalog ) helfen bei großen Projekten mehr als technische ( app/Services ). 
CODE
<?php
// app/Bestellwesen/Daten/Warenkorb.php
final readonly class WarenkorbPosition
{
    public function __construct(public int $produktId, public int $menge) {}
}

// app/Bestellwesen/Actions/BestellungAnlegen.php
final class BestellungAnlegen
{
    public function __construct(private PreisRechner $preise) {}

    /** @param list<WarenkorbPosition> $positionen */
    public function ausfuehren(User $user, array $positionen): Bestellung
    {
        return DB::transaction(function () use ($user, $positionen) {
            $bestellung = $user->kunde->bestellungen()->create(['status' => BestellStatus::Offen]);

            foreach ($positionen as $pos) {
                $produkt = Produkt::lockForUpdate()->findOrFail($pos->produktId);

                if ($produkt->bestand < $pos->menge) {
                    throw LagerbestandZuNiedrig::fuer($produkt);
                }

                $bestellung->produkte()->attach($produkt->id, [
                    'menge' => $pos->menge, 'preis_cent' => $produkt->preis_cent,
                ]);
                $produkt->decrement('bestand', $pos->menge);
            }

            BestellungAufgegeben::dispatch($bestellung);
            return $bestellung;
        });
    }
}

// Controller - nur noch Uebersetzung HTTP <-> Anwendungsfall
public function store(BestellungRequest $request, BestellungAnlegen $anlegen): RedirectResponse
{
    $bestellung = $anlegen->ausfuehren($request->user(), $request->positionen());
    return to_route('bestellungen.show', $bestellung);
}

m59-l2 Webhooks sicher empfangen
 Ein  Webhook  ist eine HTTP-Anfrage, die ein fremder Dienst an deine Anwendung schickt, wenn dort etwas passiert – „Zahlung eingegangen“, „Paket zugestellt“. Weil jeder diese Adresse aufrufen kann, gelten vier Regeln:     Signatur prüfen.  Der Dienst signiert den Body mit einem gemeinsamen Geheimnis (meist HMAC-SHA256). Du berechnest die Signatur nach und vergleichst mit  hash_equals()  – nie mit  === , weil ein normaler Stringvergleich durch Zeitmessung angreifbar ist.    Den rohen Body verwenden.  Die Signatur gilt für die exakten Bytes. Wer erst JSON dekodiert und wieder kodiert, verändert Leerzeichen oder Reihenfolge – die Prüfung schlägt fehl.    Idempotent verarbeiten.  Dienste schicken denselben Webhook bei Zeitüberschreitung erneut. Speichere die Ereignis-ID und ignoriere Wiederholungen.    Schnell antworten.  Bestätige mit 200 und verarbeite in einem Job. Wer zu lange braucht, bekommt den Webhook nochmal.    Die Webhook-Route liegt außerhalb des CSRF-Schutzes ( validateCsrfTokens(except: [...]) ) – deshalb ist die Signatur die einzige Sicherung. 
CODE
<?php
// routes/web.php
Route::post('/webhooks/zahlung', ZahlungsWebhook::class)->middleware('throttle:60,1');

// app/Http/Controllers/ZahlungsWebhook.php
class ZahlungsWebhook extends Controller
{
    public function __invoke(Request $request)
    {
        $roh       = $request->getContent();                       // exakte Bytes
        $signatur  = (string) $request->header('X-Signatur');
        $erwartet  = hash_hmac('sha256', $roh, config('services.zahlung.webhook_secret'));

        if (!hash_equals($erwartet, $signatur)) {                  // zeitkonstanter Vergleich
            abort(401);
        }

        $ereignis = json_decode($roh, true, 512, JSON_THROW_ON_ERROR);

        // Idempotenz: dieselbe Ereignis-ID nur einmal verarbeiten
        $neu = WebhookEreignis::firstOrCreate(
            ['anbieter_id' => $ereignis['id']],
            ['typ' => $ereignis['typ'], 'nutzlast' => $ereignis]
        )->wasRecentlyCreated;

        if ($neu) {
            VerarbeiteZahlung::dispatch($ereignis['id']);           // eigentliche Arbeit im Job
        }

        return response()->noContent();                            // schnell bestaetigen
    }
}

m59-l4 Echtzeit mit Broadcasting und Reverb

Ein Event mit  implements ShouldBroadcast  wird automatisch an die Browser gesendet.    broadcastOn()  legt den Kanal fest: öffentlich ( Channel ), privat ( PrivateChannel ) oder mit Anwesenheitsliste ( PresenceChannel ). <?php
// app/Events/BestellstatusGeaendert.php

{

    public function __construct(public Bestellung $bestellung) {}

    public function broadcastOn(): array
    {
        return [new PrivateChannel('bestellungen.' . $this->bestellung->id)];
    }

    public function broadcastWith(): array
    {
        return ['status' => $this->bestellung->status->value];   // nur das Noetige senden
    }
}

// routes/channels.php - wer darf mithoeren?

    return $user->id === $bestellung->kunde->user_id;
});

// Ausloesen

m50-l1 Jobs und Queues
 Alles, was länger als ein paar hundert Millisekunden dauert oder von externen Diensten abhängt, gehört  nicht in den Request : Mails, PDF-Erzeugung, Bildbearbeitung, Importe, Webhooks an Dritte. Ein  Job  beschreibt die Arbeit, die  Queue  speichert ihn, ein  Worker  ( php artisan queue:work ) arbeitet ihn im Hintergrund ab.     Treiber  Einsatz      sync   führt sofort aus – nur für lokale Tests      database   Standard in neuen Projekten, ohne Zusatzdienst      redis   Produktion mit Last, dazu  Horizon  als Dashboard      sqs   AWS, verwaltet     Jobs müssen damit rechnen,  mehrfach  zu laufen: Ein Worker stürzt mitten im Job ab, und der Job wird erneut ausgeführt. Schreibe sie deshalb  idempotent  – also so, dass ein zweiter Lauf keinen Schaden anrichtet. Die Steuerung übernehmen  $tries ,  $backoff  (Wartezeit zwischen Versuchen),  $timeout  und  failed()  für den endgültigen Fehlschlag. Gescheiterte Jobs landen in  failed_jobs  und lassen sich mit  queue:retry  erneut anstoßen.   Models im Konstruktor werden nur als ID serialisiert ( SerializesModels ) und im Worker frisch geladen. Mehrere Jobs lassen sich als  Kette  ( Bus::chain , nacheinander) oder als  Batch  ( Bus::batch , parallel mit Fortschritt) zusammenfassen. 
CODE
<?php
// app/Jobs/RechnungErzeugen.php
class RechnungErzeugen implements ShouldQueue, ShouldBeUnique
{
    use Queueable;

    public int $tries = 5;
    public int $timeout = 120;

    public function __construct(public Bestellung $bestellung) {}

    public function backoff(): array
    {
        return [10, 60, 300];             // Sekunden zwischen den Versuchen
    }

    public function uniqueId(): string
    {
        return (string) $this->bestellung->id;
    }

    public function handle(PdfDienst $pdf): void
    {
        if ($this->bestellung->rechnung_pfad) {
            return;                       // idempotent: schon erledigt
        }
        $pfad = $pdf->rechnung($this->bestellung);
        $this->bestellung->update(['rechnung_pfad' => $pfad]);
    }

    public function failed(Throwable $e): void
    {
        Log::error('Rechnung fehlgeschlagen', ['bestellung' => $this->bestellung->id, 'fehler' => $e->getMessage()]);
    }
}

// Ausloesen
RechnungErzeugen::dispatch($bestellung)->onQueue('dokumente')->afterCommit();

m50-l2 Caching-Strategien
 Ein Cache speichert teure Ergebnisse für einen schnellen Zugriff. In Laravel wählst du den Treiber in  config/cache.php :  database  (Standard),  redis ,  memcached ,  file ,  array  (nur für Tests).     Cache::remember($key, $ttl, $fn)  – holt aus dem Cache oder berechnet und speichert.    Cache::flexible($key, [$frisch, $max], $fn)  –  stale-while-revalidate : liefert kurz abgelaufene Werte sofort aus und berechnet im Hintergrund neu.    Cache::forget($key)  – gezielt invalidieren, etwa im Observer nach dem Speichern.    Cache::lock($name, $sek)  – atomare Sperre über mehrere Server hinweg.    „There are only two hard things in Computer Science: cache invalidation and naming things.“ Die beiden üblichen Strategien zur Invalidierung sind:     Strategie  Funktionsweise  Risiko     Ablaufzeit (TTL)  Wert verfällt nach x Sekunden  bis zu x Sekunden veraltete Daten     Ereignisgesteuert  bei Änderung löschen  eine vergessene Schreibstelle hinterlässt veraltete Werte     Versionierter Schlüssel   produkt:{id}:{updated_at}   alte Schlüssel bleiben bis zum Verfall liegen     Bei sehr vielen gleichzeitigen Anfragen auf einen gerade abgelaufenen Schlüssel berechnen alle gleichzeitig neu – der  Cache-Stampede .  flexible()  oder ein Lock verhindern das. 
CODE
<?php
// Teure Startseiten-Daten fuer 10 Minuten
$bestseller = Cache::remember('startseite:bestseller', now()->addMinutes(10), function () {
    return Produkt::aktiv()
        ->withCount('bestellungen')
        ->orderByDesc('bestellungen_count')
        ->take(12)
        ->get();
});

// Stale-while-revalidate: 5 Min. frisch, bis 15 Min. ausliefern und im Hintergrund erneuern
$kennzahlen = Cache::flexible('dashboard:kennzahlen', [300, 900], fn () => Kennzahlen::berechnen());

// Versionierter Schluessel - keine explizite Invalidierung noetig
$html = Cache::rememberForever(
    "produkt:{$produkt->id}:{$produkt->updated_at->timestamp}:karte",
    fn () => view('produkte._karte', compact('produkt'))->render()
);

// Atomare Sperre: nur ein Server fuehrt den Import aus
Cache::lock('import:lieferant-42', 600)->get(function () {
    app(LieferantenImport::class)->ausfuehren(42);
});

m50-l4 Scheduler und Artisan-Commands
 Statt vieler Cron-Einträge auf dem Server brauchst du mit Laravel genau  einen :    * * * * * cd /var/www/shop &amp;&amp; php artisan schedule:run &gt;&gt; /dev/null 2&gt;&amp;1    Alle geplanten Aufgaben stehen dann versioniert im Code, in  routes/console.php . Eigene  Artisan-Commands  ( make:command ) kapseln Wartungsaufgaben, Importe und Berichte. Die Signatur beschreibt Argumente und Optionen, Laravel erzeugt daraus die Hilfe. CODE
<?php
// app/Console/Commands/AlteWarenkoerbeLoeschen.php
class AlteWarenkoerbeLoeschen extends Command
{
    protected $signature = 'shop:warenkoerbe-aufraeumen
                            {--tage=30 : Warenkoerbe aelter als so viele Tage}
                            {--dry-run : Nur anzeigen, nichts loeschen}';

    protected $description = 'Loescht verwaiste Warenkoerbe';

    public function handle(): int
    {
        $grenze = now()->subDays((int) $this->option('tage'));
        $query  = Warenkorb::whereNull('bestellung_id')->where('updated_at', '<', $grenze);

        $anzahl = $query->count();
        if ($this->option('dry-run')) {
            $this->info("{$anzahl} Warenkoerbe wuerden geloescht.");
            return self::SUCCESS;
        }

        $query->delete();
        $this->info("{$anzahl} Warenkoerbe geloescht.");
        return self::SUCCESS;
    }
}

Art  Prüft  Geschwindigkeit     Unit-Test  eine Klasse isoliert, ohne Framework  sehr schnell     Feature-Test  einen HTTP-Request durch die ganze App, mit Datenbank  schnell genug, größter Nutzen     Browser-Test  echtes JavaScript im Browser (Dusk, Pest-Browser-Plugin)  langsam     In Laravel-Projekten bringen  Feature-Tests  den meisten Nutzen pro Zeile: Sie prüfen Routing, Validierung, Autorisierung, Datenbank und Antwort zusammen. m51-l3 Codequalität: Pint, Larastan und CI
 Qualität entsteht nicht durch Disziplin allein, sondern durch  Automatisierung . Drei Werkzeuge gehören in jedes ernsthafte Laravel-Projekt:     Laravel Pint  formatiert den Code einheitlich ( ./vendor/bin/pint ). Diskussionen über Leerzeichen und Klammern entfallen. m51-l4 Deployment und Sicherheit in Produktion
 Ein Deployment muss  wiederholbar  sein – ein Skript, kein Gedächtnisprotokoll. Die Standardschritte:    Code holen,  composer install --no-dev --optimize-autoloader    Frontend bauen ( npm ci &amp;&amp; npm run build )    php artisan migrate --force  (ohne  --force  fragt Laravel in Produktion nach)    php artisan optimize  (Config, Routen, Events, Views cachen)    php artisan queue:restart , PHP-FPM neu laden (wegen OPcache)     Zero-Downtime-Deployments  bauen jedes Release in einem eigenen Verzeichnis auf und schalten am Ende nur einen Symlink  current  um. Migrationen müssen dafür  abwärtskompatibel  sein: Eine Spalte erst hinzufügen, Code umstellen und erst in einem späteren Release die alte Spalte entfernen.     Prüfpunkt  Produktion      APP_ENV    production       APP_DEBUG    false  – sonst zeigt die Fehlerseite Code, Pfade und Umgebungswerte      APP_KEY   gesetzt, geheim, nie wechseln ohne Plan (sonst sind Sessions und verschlüsselte Daten unlesbar)     HTTPS  überall, mit HSTS-Header     Document Root  nur  public/      Uploads  validiert ( mimes ,  max ), außerhalb von  public/  oder in S3, nie mit Benutzer-Dateinamen     Abhängigkeiten   composer audit  regelmäßig, Updates zeitnah     Fehler  an Logging-/Monitoring-Dienst, nicht nur in  storage/logs

<?php

    : Password::min(8));

// Sicherheits-Header als Middleware
class SicherheitsHeader
{
    public function handle(Request $request, Closure $next): Response
    {
        $antwort = $next($request);
        $antwort->headers->set('X-Content-Type-Options', 'nosniff');
        $antwort->headers->set('Referrer-Policy', 'strict-origin-when-cross-origin');
        $antwort->headers->set('Strict-Transport-Security', 'max-age=31536000; includeSubDomains');
        return $antwort;
    }
}

Log::withContext([...])  hängt Informationen an alle folgenden Einträge einer Anfrage – etwa eine Request-ID oder die Benutzer-ID. Damit lässt sich ein Fehler über alle Einträge hinweg verfolgen. <?php
// Middleware: jede Anfrage bekommt eine ID, die in jedem Log-Eintrag steht
class RequestId
{
    public function handle(Request $request, Closure $next): Response
    {
        $id = $request->header('X-Request-Id') ?: (string) Str::uuid();
        Log::withContext(['request_id' => $id, 'user_id' => $request->user()?->id]);

        $antwort = $next($request);
        $antwort->headers->set('X-Request-Id', $id);
        return $antwort;
    }
}

Tests als Liste  aus der Planung übernehmen und als leere Pest-Tests anlegen.    Datenbank zuerst : Migration, Model, Factory.    Fachlogik  in einer Action, mit Unit- oder Feature-Test.    HTTP-Schicht : Route, Form Request, Policy, Controller, View oder Resource.    Qualität :  pint ,  phpstan ,  php artisan test  – alles grün.    Pull Request  mit Beschreibung, Review, Merge.
