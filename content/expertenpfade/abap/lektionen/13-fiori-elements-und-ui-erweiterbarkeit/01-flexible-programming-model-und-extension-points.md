# Flexible Programming Model & Extension Points

*Fiori Elements & UI-Erweiterbarkeit · ca. 6 Min.*

Fiori Elements bietet definierte **Extension Points** (eigene Custom Sections, Custom Actions, Custom Columns über Controller-Extensions), um punktuell von der reinen Annotation-Steuerung abzuweichen, ohne komplett auf Freestyle-UI5 umzusteigen — das **Flexible Programming Model** ist genau dieser Mittelweg.

> **Tipp:** Bevor eine Anforderung als Grund für kompletten Freestyle-Code herhält, lohnt sich immer die Prüfung, ob ein Fiori-Elements-Extension-Point ausreicht — das bewahrt den Großteil der generierten Standard-UI und minimiert Wartungsaufwand.

## Kontrollfragen

**1. Was ist das Flexible Programming Model?**

- [x] Ein Mittelweg zwischen reiner Annotation-Steuerung und komplettem Freestyle-UI5
- [ ] Ein Ersatz für OData V4
- [ ] Eine Testmethode für RAP

*Erklärung:* Es erlaubt punktuelle Erweiterung der generierten UI über definierte Extension Points.

**2. Was ist ein Beispiel für einen Fiori-Elements-Extension-Point?**

- [x] Eine Custom Section/Custom Action über Controller-Extensions
- [ ] Eine neue Datenbanktabelle
- [ ] Ein AMDP-Verfahren

*Erklärung:* Controller-Extensions binden zusätzliche UI-Logik gezielt in die generierte App ein.
